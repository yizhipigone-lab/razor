## 一、项目背景

### 1.1 起因

用户在深入了解睿奕量化平台的实盘交易机制后，发现三个影响日常使用的问题：

1. **策略名写死**：TDX 选股公式名 "QUANTQQ" 在选股→信号转发→实盘记录全链路硬编码，前端改了公式名后，后端还是用老名字
2. **扫描间隔写死**：实盘离场扫描间隔硬编码 60 秒，盘中波动快时反应慢
3. **注释误导**：代码里到处写着 "Docker"，但项目实际是纯 Windows 本机部署，新接手的人会被误导

此外还发现两个隐藏的 BUG：
- **信号转发连接失败**：`LIVE_TRADER_URL` 默认值用了 `host.docker.internal`，在 Windows 环境下无法解析
- **asyncio 模块缺失**：`live_trader/main.py` 的 `_process_one_signal()` 使用 `asyncio.to_thread()` 但没有模块级 import

### 1.2 用户需求清单

| # | 需求 | 优先级 | 说明 |
|---|------|--------|------|
| 1 | 策略名全链路动态化 | 🔴 高 | 前端改公式名后，选股/信号/实盘记录全部用新名字 |
| 2 | 离场扫描间隔可配置 | 🟠 中 | 默认 60s 不变，用户可调低到 10s |
| 3 | 误导性 Docker 注释纠正 | 🟡 中 | 实际不用 Docker，注释不能骗人 |
| 4 | 项目 README | 🟢 低 | 项目没有 README，新人无从下手 |
| 5 | 功能清单 | 🟢 低 | 合并入 README |

### 3.1 Task 3：误导性 Docker 注释纠正 + 连接 BUG 修复

> Commit: `3e68cff` (F1 紧急修复) + `c17a0ed` (注释纠正 + F2-F4 防御性改进)

#### 3.1.1 F1 紧急修复：信号转发连接失败

**问题**：`cron_jobs.py:544` 的 `LIVE_TRADER_URL` 默认值是 `http://host.docker.internal:8001`，在 Windows 环境下无法解析，导致信号转发 100% 失败。

**修复**：

```python
# 修复前
live_url = os.environ.get("LIVE_TRADER_URL", "http://host.docker.internal:8001")

# 修复后
live_url = os.environ.get("LIVE_TRADER_URL", "http://127.0.0.1:8001")
```

**影响**：这是一个 **生产环境正在触发的真实 BUG**。每次定时选股后信号转发到实盘服务都会失败。修复后信号可以正常到达 8001 端口。

#### 3.1.2 F2-F4 防御性改进

3 处 `host.docker.internal` 默认值（`qmt.py`、`data_sync.py`、`qmt_index_sync.py`）已被 `.env` 中 `QMT_PROXY_HOST=127.0.0.1` 覆盖，当前不触发 BUG，但默认值写错了，新部署会踩坑。

全部改为 `127.0.0.1`，Docker 环境可通过环境变量覆盖。

#### 3.1.3 注释纠正（23 处）

| 区域 | 数量 | 典型修改 |
|------|------|---------|
| `live_trader/` 内 | 9 处 | "Docker 端 qmt_gateway" → "API 服务端 qmt_gateway" |
| `live_trader/` 外 | 10 处 | "[DOCKER-NET]" → "[PROXY-NET]" |
| 模块文档 | 4 处 | "Docker 环境" → "非 Windows 环境" |
| 历史命名注释 | 1 处 | store.py:602 上方添加"历史命名,实际为 API 服务端信号"说明 |

**source 名保留**：数据库中的 `docker_tdx` source key 不改（数据库 source key 是历史数据标识，改了会导致对账匹配失败）。

### 3.3 Task 2：离场扫描间隔可配置化

> Commit: `a20fdd4`

#### 3.3.1 需求

实盘离场扫描间隔硬编码 60 秒（`scheduler.py:138`），盘中波动快时反应慢。用户希望可调低到 10 秒，但默认保持 60 秒不变（避免破坏性变更）。

#### 3.3.2 技术方案

`LiveTraderConfig` 是 `frozen=True` 的 dataclass，运行时不可修改。方案：在 `LiveScheduler` 中维护独立的 `_exit_scan_interval` 可变属性，提供 `set_scan_interval()` / `get_scan_interval()` 方法。

```
前端保存
  ↓ PUT /live/config/scan-interval {interval_sec: 30}
main.py 端点
  ↓ scheduler.set_scan_interval(30)     ← 内存立即生效
  ↓ settings.set("live_trader",         ← 持久化到 app_setting.json
       "exit_scan_interval_sec", 30,
       save=True)
下次启动
  ↓ load_config() 从 app_setting.json 读取 exit_scan_interval_sec=30
  ↓ LiveScheduler.__init__ 从 config 读取
```

#### 3.3.3 具体改动

**1. LiveTraderConfig 新增字段**

```python
# app/live_trader/config.py
@dataclass(frozen=True)
class LiveTraderConfig:
    ...
    # ===== 离场扫描 =====
    exit_scan_interval_sec: float = 60.0    # 离场扫描间隔(默认60s,可调低至10s)
```

**2. load_config() 加载新字段**

```python
config = LiveTraderConfig(
    ...
    exit_scan_interval_sec=float(cfg_dict.get("exit_scan_interval_sec", 60.0)),
)
```

**3. LiveScheduler 可运行时修改**

```python
class LiveScheduler:
    def __init__(self, config, ...):
        ...
        self._exit_scan_interval: float = getattr(config, 'exit_scan_interval_sec', 60.0)

    def set_scan_interval(self, seconds: float) -> None:
        """运行时修改离场扫描间隔(前端保存后立即生效,不阻塞)"""
        seconds = max(10.0, min(300.0, float(seconds)))  # 限制 [10, 300]
        self._exit_scan_interval = seconds

    def get_scan_interval(self) -> float:
        return self._exit_scan_interval
```

**4. 硬编码替换**

```python
# 修复前
if time.time() - self._last_scan_time < 60:

# 修复后
if time.time() - self._last_scan_time < self._exit_scan_interval:
```

**5. API 端点**

```
GET  /live/config/scan-interval     → {"interval_sec": 60}
PUT  /live/config/scan-interval     → {"interval_sec": 30, "saved": true}
```

PUT 端点同时改内存 + 持久化到 settings，保证保存即生效 + 重启不丢配置。

**6. 前端 UI**

在实盘交易 Tab 的"操作"区新增：

```html
<span>离场扫描间隔:</span>
<input type="number" id="live-scan-interval" min="10" max="300" step="5">
<span>秒</span>
<button onclick="saveScanInterval()">保存</button>
<span id="live-scan-interval-msg"></span>
```

切换到实盘 Tab 时自动加载当前间隔值（`loadScanInterval()`），保存后显示确认消息。

**7. 配置文件默认值**

```json
// config/app_setting.json
{
  "live_trader": {
    "exit_scan_interval_sec": 60
  }
}
```

#### 3.3.4 安全校验

| 校验层 | 规则 |
|--------|------|
| 前端 | `min="10" max="300"` + JS 校验 `isNaN / < 10 / > 300` |
| 后端 PUT 端点 | 参数缺失→400，非数字→400，范围越界→400 |
| scheduler.set_scan_interval | `max(10.0, min(300.0, ...))` 双重兜底 |
