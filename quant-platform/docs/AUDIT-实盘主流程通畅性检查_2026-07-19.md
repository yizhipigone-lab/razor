# 实盘主流程通畅性审计报告

> 日期：2026-07-19
> 范围：配置→止盈止损→盘中监控→尾盘下单→记账→盘中改参数生效（5 环节串联）
> 方法：5 路并行 Explore agent 分读真实代码（明确不重叠范围、禁止派子 agent），关键 FAIL 由主控交叉验证

## 总结论

主流程"配置→止盈止损→盘中监控→下单→记账"**主体能跑通**，但存在 **2 个 FAIL 级断点**，正好都落在用户最关心的"修改止盈止损 + 盘中实时生效"这条链上：

- **FAIL-A（环节1）**：2 个风控参数 key 名拼写错误，配置改了运行时读不到，永远走默认值。
- **FAIL-B（环节5）**：写配置的进程（8888）和实盘进程（8001）是两个独立进程，实盘进程启动时读一次配置就再也不刷新，改完必须重启才生效。

两者叠加 → **"改止盈止损盘中实时生效"这个目标目前完全没实现**。

## 5 环节结论表

| 环节 | 结论 | 一句话 |
|---|---|---|
| 1 系统配置→止盈止损 | **FAIL** | 真相源是 `app/config/risk_params.py`（非 `live_trader/config.py`）；2 个 key 拼错致配置静默失效 |
| 2 实盘盘中监控引用 | **PASS**（2 WARNING） | 真走 `exit_rule_engine.check`，参数共享 `load_risk_params`，现价优先实时 tick |
| 3 尾盘通达信信号→下单 | **WARNING** | 真接通达信 `tqcenter` + 真下 QMT `xtquant`；风险在信号静默丢失 |
| 4 记录交易/持仓 | **WARNING** | 实盘走 DuckDB UPSERT（幂等）；风险在卖出失败静默致账目不一致 |
| 5 改完盘中实时生效 | **FAIL** | 跨进程，`live_trader` 无 reload/watchdog，止盈止损唯一缺 PUT 写端点 |

## 致命问题（FAIL，必修）

### FAIL-A：`risk_params.py` key 拼写错误（环节1）

读取层与配置层 key 对不上（已主控交叉验证 `app_setting.json` 实际 key）：

| `app/config/risk_params.py` 读取 | `config/app_setting.json` 实际 | 后果 |
|---|---|---|
| `:58 _g("trailing_drawdown_pct", 2.0)` 缺 `_stop` | `trailing_stop_drawdown_pct = 1.7` | 配 1.7% 钉死 fallback **2.0%** |
| `:63 _g("time_exit_min_pnl_pct", 3.0)` 用 `_pnl_` | `time_exit_min_profit_pct = 2.5` | 配 2.5% 钉死 fallback **3.0%** |

旁证：API writer（`app/api/backtest.py:500,515,542,568`）、前端（`static/js/live_trader.js:531-532`）、一致性校验（`core/settings.py:55-56`）全部用正确 key，唯独读取层漏写。

测试盲点：`tests/test_risk_params.py:206` 的 `expected_keys` 沿用错误 key，`assert hit >= 8` 阈值过松（11/13 命中仍绿灯），bug 被测试掩盖。

### FAIL-B：止盈止损参数盘中无法热加载（环节5）

- 写参数：`POST /api/settings/risk-params`（`app/api/backtest.py:530-581`）跑在主 API 进程（端口 8888），只 `settings.reload()` 刷新**自己进程**的内存 + 落盘，不通知 live_trader。
- 读参数：实盘 `live_trader`（端口 8001，`start.bat:26` 独立进程）的 `Settings._data` 在 `__new__` 时一次性缓存（`core/settings.py:23-39`），生命周期内不再读盘。
- **交叉验证**：`grep reload|watchdog|PollingObserver|inotify app/live_trader/` → **0 匹配**。
- **交叉验证**：`live_trader/main.py` 中 `risk-params` 仅 `@app.get`（`:1497`），无对应 `@app.put`/`@app.post`。
- 反差对照：同文件 `scan-interval`(`:1265`)、`buy-ratio`(`:1330`)、`switches`(`:1386`) 全部有 PUT 热更新端点，**止盈止损是唯一漏掉写端点的运行时可变配置**。
- 后果：出现"模拟盘按新止损跑、实盘按旧止损跑"的口径分裂；改完必须重启 live_trader 进程。

## WARNING 级（建议修）

1. **实盘只吃 `top` 单信号，不吃叠加栈**（`CONTEXT.md:47` 已登记的显式缺口；`exit_monitor.py:67-68` 调 `check` 而非 `check_all`；`MAX_SELL_PER_SCAN=3` 是流量控制非吃栈）。
2. **`peak_price` 按 3s 采样滞后**（`store.py:976-977` 用 last 而非 today_high），快速冲高-回落行情 trailing/breakeven 可能漏触发；建议 `peak = max(local.peak, today_high)` 兜底（对齐 `sim_trader/intraday_monitor.py:176-177`）。
3. **`today_high/low` 用 QMT 当日 OHLC**（`exit_monitor.py:129-130,174-180`），瞬时触及后回撤会延迟到下次扫描才触发（默认 60s，可调 10s），成交价与触发时刻可能差距大。
4. **QMT 取价失败信号全丢且看门狗不告警**（`signal_picker.py:93-113` + `scheduler.py:429-444` + `scheduler.py:375` 把 `no_signal` 当正常）。
5. **选股失败当日不重试**（`scheduler.py:191-193` 占位防重入设计，真钱"宁漏买不重买"）。
6. **卖出 `apply_sell_fill` 失败被静默 try/except 接住**（`callback_handler.py:411-427`），单笔 deal 已入库但持仓未减，当下账目不一致只能靠重启补救。
7. **WAL 写失败静默吞**（`store.py:207-208` 只 `logger.error` 不抛）。
8. **4 个核心开关写死不可配置**（`exit_rules.py:424-427`：`priority_mode="trailing_first"` / `tp_stack_mode` / `tp1_fill_pct=0.03` / `realistic_stop_fill`），尤其 `priority_mode` 决定快跌时止盈/止损谁先执行。
9. **第二处默认值漂移源**：`RuleContext` 字段默认值（`exit_rules.py:67-106`）与 `RiskParams` fallback 默认值并存，当前数值巧合一致，任一方单独改动即静默漂移。

## 修复优先级建议

- **P0-1**：修 2 个 key（`risk_params.py:58,63` 改 2 行 + 同步 `tests/test_risk_params.py:206` 的 `expected_keys`）—— 立即。
- **P0-2**：给 `live_trader` 加 `PUT /live/config/risk-params` 写端点，内部 `settings.reload()` + 通知 exit_monitor —— 真正实现盘中生效。
- **P1**：卖出失败不静默 / 信号丢失看门狗告警 / `peak_price` 用 `today_high` 兜底。
- **P2**：实盘吃叠加栈（`exit_monitor` 改扫描模型 + `MAX_SELL_PER_SCAN`）/ 选股失败有限重试。
