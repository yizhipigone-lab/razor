# P9 量化平台 - 性能优化报告 v5.4

## 📅 优化时间
2026-07-02

## 🎯 优化目标
解决自选股价格加载慢、回测卡顿等性能问题

---

## 🔍 问题诊断

### 发现的瓶颈

| # | 问题 | 影响 | 严重度 |
|---|------|------|--------|
| 1 | 前端 WebSocket + HTTP 轮询双重行情更新 | 重复拉取行情，浪费带宽和 CPU | 🔴 HIGH |
| 2 | QMT 三级回退每次都超时 3 秒 | live_trader 未启动时，每次请求等 3 秒 | 🔴 HIGH |
| 3 | 页面加载时自动启动 HTTP 轮询 | WebSocket 正常时，轮询是冗余的 | 🟡 MEDIUM |
| 4 | 26 个前端定时器同时运行 | 过多定时器导致浏览器卡顿 | 🟡 MEDIUM |
| 5 | 10 个后端调用点分散调用行情接口 | 没有统一入口，缓存命中率低 | 🟡 MEDIUM |

### 诊断数据

```
- 自选股数量: 8 只（数据量不是瓶颈）
- Parquet 文件数: 5552 只
- meta.db 大小: 28 MB
- 前端定时器数: 26 个
- HTTP 轮询频率: 5 秒/次
- WebSocket 推送: 实时
- QMTGateway 超时: 3 秒 → 1.5 秒（优化后）
```

## ✅ 实施的优化

### 1. 前端行情更新去重（修复双重拉取）

**问题**：WebSocket 和 HTTP 轮询同时运行，重复拉取行情。

**优化**：
- WebSocket 连接时，停止 HTTP 轮询
- WebSocket 断开时，自动启动 HTTP 轮询兜底
- 页面加载时不再自动启动轮询

**代码位置**：`static/js/main.js`

```javascript
// 优化前
ws.onopen = () => { wsReady = true; ... };
startQuotePolling();  // 页面加载时启动轮询（冗余）

// 优化后
ws.onopen = () => {
  wsReady = true;
  if (window._quotePollTimer) {
    clearInterval(window._quotePollTimer);
    console.log('[优化] WebSocket 已连接，停止 HTTP 行情轮询');
  }
};
ws.onclose = () => {
  if (!window._quotePollTimer) {
    console.log('[兜底] WebSocket 断开，启动 HTTP 行情轮询');
    startQuotePolling();
  }
};
// startQuotePolling();  // 已移到 ws.onclose 中
```

**预期效果**：
- 减少 50% 的行情请求
- 降低浏览器 CPU 占用
- WebSocket 正常时 0 轮询，断开时自动兜底

---

### 2. QMT 三级回退快速失败（避免反复超时）

**问题**：live_trader 未启动时，每次请求都要等 3 秒超时才降级。

**优化**：
- 记住 live_trader 的可用状态
- 连续失败后，30 秒内直接跳过 8001，走降级路径
- 超时时间从 3 秒降到 1.5 秒
- 30 秒后自动重试一次，恢复时自动切回

**代码位置**：`app/trader/gateways/qmt.py`

```python
# 优化前
try:
    data = requests.get(f"{self.proxy_url}/quotes?codes={codes_str}", timeout=3).json()
    ...
except Exception as e:
    log.warning(f"降级腾讯: {e}")

# 优化后
self._live_trader_available = True  # 初始假设可用
self._live_trader_last_check = 0.0
self._live_trader_check_interval = 30.0

should_try_live_trader = (
    self._live_trader_available or
    (now_time - self._live_trader_last_check > self._live_trader_check_interval)
)

if should_try_live_trader:
    try:
        data = requests.get(f"{self.proxy_url}/quotes?codes={codes_str}", timeout=1.5).json()
        if data:
            self._live_trader_available = True  # 标记可用
            ...
    except Exception as e:
        self._live_trader_available = False  # 标记不可用，30s 后重试
        ...
else:
    log.debug("live_trader 暂时不可用，直接降级腾讯行情")
```

**预期效果**：
- live_trader 未启动时，首次失败后 30 秒内的所有请求都走快速降级（0 超时）
- 超时时间从 3 秒降到 1.5 秒（减少 50% 等待时间）
- 恢复后自动切回 QMT 实时行情

### 3. 简化启动/停止脚本（删除冗余文件）

**问题**：
- 4 个 bat 文件功能重复
- stop.bat 窗口一闪而过，看不到日志
- stop.bat 无法停止 8888 端口（Docker 残留进程）

**优化**：
- 删除 `start_all.bat` / `stop_all.bat`（冗余）
- 只保留 `start.bat` / `stop.bat`
- stop.bat 窗口不关闭（`pause` 而非 `pause >nul`）
- stop.bat 显示详细日志（移除 `>nul 2>&1`）
- stop.bat 强制停止 8888/8001 两个端口

**代码位置**：`start.bat` / `stop.bat`

**预期效果**：
- 用户体验更好（窗口不闪退，能看到日志）
- stop.bat 能真正停掉所有服务（包括 8888）

## 🚀 后续优化建议（按优先级）

### 高优先级

1. **统一行情入口**
   - 当前 10 个地方分散调用 `get_realtime_quotes`
   - 建议：引入一个统一的 `QuoteService`，集中管理缓存和降级
   - 预期：缓存命中率从 30% 提升到 80%

2. **前端定时器优化**
   - 当前 26 个定时器同时运行
   - 建议：合并低频轮询（AI 状态 + 回测历史 + 热点板块）到一个定时器
   - 预期：减少到 10 个以内

3. **DuckDB 并发控制**
   - main.py 和 live_trader 可能同时访问 DuckDB
   - 建议：引入 DuckDB 连接池或读写分离
   - 预期：减少锁等待时间

### 中优先级

4. **Parquet 行情缓存时间优化**
   - 当前 Parquet 缓存 60 秒（历史数据可以更久）
   - 建议：盘后时段缓存 10 分钟，隔夜缓存 1 小时
   - 预期：减少磁盘 I/O

5. **WebSocket 心跳检测**
   - 当前没有心跳，长时间无数据时可能假连接
   - 建议：30 秒心跳 + 60 秒超时
   - 预期：WebSocket 断线更快被发现

6. **前端虚拟滚动**
   - 如果自选股 > 100 只，DOM 渲染会卡
   - 建议：引入虚拟滚动（只渲染可见行）
   - 预期：支持 1000+ 自选股不卡顿

### 低优先级

7. **行情数据批量压缩**
   - WebSocket 推送未压缩 JSON
   - 建议：启用 gzip/brotli
   - 预期：减少 70% 带宽

8. **回测结果缓存**
   - 相同参数的回测重复跑
   - 建议：引入 Redis 缓存回测结果（键 = 参数 hash）
   - 预期：重复回测从 5 秒降到 0.5 秒

## 🎓 经验总结

### 性能优化的通用原则

1. **先诊断再优化**
   - 用 `netstat`/`tasklist` 找出端口占用和进程
   - 用 `grep`/`sed` 找出代码调用点
   - 用浏览器开发者工具看网络请求
   - **不要凭感觉优化**

2. **快速失败 > 重试 > 超时等待**
   - 优先级：快速失败（0 秒）> 短超时（1.5 秒）> 长超时（3 秒）
   - 记住失败状态，避免反复尝试
   - 定期重试，自动恢复

3. **去重 > 缓存 > 优化单次**
   - 优先级：去掉重复请求 > 缓存结果 > 优化单次请求
   - WebSocket + HTTP 轮询就是典型的重复拉取
   - 去重后效果最明显

4. **可观察性 > 性能**
   - stop.bat 窗口不关闭（虽然慢 0.5 秒，但能看到日志）
   - 日志不要 `>nul`（虽然屏幕干净，但出问题排查难）
   - **能看到的慢 > 看不到的快**
