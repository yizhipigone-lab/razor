## 3. v1.2.2 漏洞修复对应

| 漏洞 | 严重度 | 修复方式 | 修复位置 |
|------|--------|----------|----------|
| **A: 同股重复信号 = 全部幂等** | P0 | buy-signal 端点内部 `unique_signals = {s.code: s for s in req.signals}.values()` 去重，保留第一条 | main.py `_process_one_signal` 之前 |
| **B: code 格式不一致 = 冷却失效** | P0 | ① store 所有 upsert 入口统一 `format_code()` ② 闸门 10 入口 `format_code()` ③ store 查询也做模糊匹配 | store.py + risk_gate.py |
| **C: Docker 不解析响应 = 状态错乱** | P0 | 转发函数解析 `resp.json()` 的 accepted/rejected，按 code 标记每个信号状态（acked/rejected/unknown） | cron_jobs.py `_forward_signals_to_live_trader` |
| **D: service 等 callback = 时序爆炸** | P1 | `place_order_service` 只等 `seq` 返回，不等 callback。callback 由 CallbackHandler 异步处理 | main.py `place_order_service` |
| **E: 14:55 误拒** | P1 | buy-signal 端点分段策略：14:55-14:57 五档即成即撤(42/47)，14:57-14:59 对手最优(44)，14:59+ 才拒收 | main.py `_process_one_signal` + config `buy_signal_cutoff` |
| **F: service volume 契约** | P1 | `volume=0 + amount` 触发 `_calc_buy_volume()` 自动计算；`volume>0` 直接用。/live/order 传 volume，buy-signal 传 amount | main.py `place_order_service` + buy_volume.py |

## 5. 双重开关（§3 实现）

| 字段 | 位置 | 作用 | 默认 |
|------|------|------|------|
| `AUTO_BUY` | sim_trader/config.py | 控制模拟盘是否执行买入 | True |
| `LIVE_SIGNAL_MODE` | sim_trader/config.py（从 app_setting.json 读） | 控制是否转发到实盘 | `"off"` |

**组合语义**:

| AUTO_BUY | LIVE_SIGNAL_MODE | 效果 |
|----------|------------------|------|
| False | 任意 | 模拟盘不买，实盘也没信号 |
| True | off | 模拟盘买，实盘不转发 |
| True | sim_only | 模拟盘买（等同 off，显式声明） |
| True | sim_and_live | 模拟盘买 + 实盘真买 |

**前端/ API 兼容**:
- `POST /api/settings/sim-switches` 新增 `live_signal_mode` 字段（旧客户端不传则保持原值）
- 原有 `auto_buy` 开关照常工作

## 6. 买入量计算（§6 实现）

```
单只金额(软上限) = config.buy_position_size (默认 10000)
闸门1 上限(硬)   = LIVE_CAPITAL × 0.20

实际金额 = min(单只金额, 闸门1 上限)
估算股数 = 实际金额 / price
取整股数 = _calc_buy_volume(code, 估算股数, price)
实际买入 = 取整股数 × price
再经 RiskGate 闸门 3/4 校验
```

**板块取整规则**:

| 板块 | 代码前缀 | 最小单位 | 示例 |
|------|----------|----------|------|
| 主板/创业板 | 0/3/6(非688) | 100 股 | 10000/10=1000→1000 |
| 科创板 | 688 | 200 股 | 10000/20=500→400 |
| 北交所 | 8/4/920 | 100 股 | 10000/8=1250→1200 |

## 7. 时序保证

```
Docker(14:52)                          Windows(8001)
─────────────                          ─────────────
cron 14:52 → TdxBridge 选股
   → engine.execute_buy()（模拟盘照常）
   → LIVE_SIGNAL_MODE=sim_and_live?
      → 探活 GET /live/health (1s)
         失败 → 存 pending + 告警
      → POST /live/buy-signal (7s,含1次重试)
         失败 → 重试1次(3s)
                                        → 14:59 前才拒收
                                        → 鉴权 Bearer token
                                        → 信号去重(漏洞A)
                                        → Semaphore(3) 并发处理
                                        → 每个: QMT实时价覆盖(漏洞B)
                                           → 幂等 MD5("buy_signal"|code|date)
                                           → 闸门10 同股冷却(漏洞B)
                                           → RiskGate 10闸门
                                           → ClearanceLock wait 5s(§10.1)
                                           → _calc_buy_volume
                                           → price_type 分段(漏洞E)
                                           → place_order_service
                                           → 心跳记录
   → 解析响应(漏洞C)
   → 更新 signal_state.json
```

**总时间**: 5 只信号 × (5s 锁等 + 3s 下单) / 3 并发 ≈ 13s，远小于尾盘 3 分钟窗口。
