### 🔴 A-1 (严重):P1-5 Position 序列化补全指向了错误的代码块

# store.py 中有两个类:
classes = ['SimTraderStore', 'JsonSimStore']

# SimTraderStore(DuckDB 实现)— store.py 实际内容
def save_positions(self, positions):

### 🟡 A-2 (中等):P0-4 一致性校验阈值"1.2 倍"偏松,建议改 1.1

**计划书原话**:
> 若 `equity_curve` 非空且首条 `equity > INITIAL_CAPITAL * 1.2` → log.error 告警 + 拒绝采用该曲线

**实测的真实数据**:

| 场景 | 首条 equity | INITIAL_CAPITAL | 比值 |
|---|---|---|---|
| TDX 污染数据 | 2,139,705 | 1,000,000 | **2.14x** |
| 实盘重置后首日(无交易) | 1,000,000 | 1,000,000 | 1.00x |
| 实盘重置后首日(有交易) | 1,000,000 ± 10% | 1,000,000 | 0.90 ~ 1.10 |

**问题**:
- 1.2x 阈值会放过 1.0x ~ 1.2x 的可疑数据(给未来回测脚本留缝)
- 实盘首日不太可能超过 1.10x(单日盈亏超过 10% 罕见,且要正好是首日)

**建议修订**:
```python
# 阈值改为 1.10,更安全
if equity_curve and equity_curve[0].get('equity', 0) > INITIAL_CAPITAL * 1.10:
    log.error(
        f"⚠️ 拒绝采用可疑 equity_curve:首条 equity={...} "
        f"超过 INITIAL_CAPITAL({INITIAL_CAPITAL}) 的 1.10 倍,"
        f"疑似被 TDX 回测数据污染"
    )
    self.equity_curve = []  # 重置为空,阻止虚假曲线进入内存
```

### 🟡 A-3 (中等):P0-4 "拒绝采用"含义不清,三种理解差异大

**计划书原话**:
> 拒绝采用该曲线

**三种可能理解**:
- 选项 A:不加载 equity_curve,但保留 cash/positions/trades(温和,推荐)
- 选项 B:不加载整个 state.json,要求人工清理(强制)
- 选项 C:拒绝启动(API 返回 500,激进)

**我推荐 A**,理由:
- B 会让所有 API 都 503,影响其他功能
- C 是规则 3 禁止的"破坏启动流程"
- A 让系统能继续跑(现金和持仓可能还有用),但把虚假曲线挡掉

**建议补充明确写法**:
```python
if equity_curve and equity_curve[0].get('equity', 0) > INITIAL_CAPITAL * 1.10:
    log.error(f"⚠️ equity_curve 首条 = {ec[0]['equity']:.0f} 超过 110 万,疑似污染")
    self.equity_curve = []  # 选项 A:仅丢弃曲线
    # 同时记录到全局告警,让 API 可以查询
    _BAD_EQUITY_CURVE_DETECTED = True
```

### 🟡 A-4 (细节):reset API 清零后引擎不会立即补当日快照

**计划书原话**:
> P0-3 调 `POST /api/sim-trader/reset` 或离线等价操作

**reset 实际实现**(API L534-546 已验证):
```python
async def sim_trader_reset():
    global _engine
    with _engine_lock:
        from app.sim_trader.engine import SimTraderEngine
        from app.sim_trader.store import JsonSimStore
        store = JsonSimStore()
        store._data = {}
        store._save()
        _engine = SimTraderEngine(store=store)
    log.info("模拟盘已重置")
    return {'status': 'ok', 'message': '模拟盘已重置为初始状态'}
```

**行为**:
- ✅ state.json 清空 ✓
- ✅ 重新 new 一个 SimTraderEngine(走 __init__ → _fill_missing_snapshots,但因 equity_curve 为空直接 return)
- ⚠️ **不会立即调用 record() 补当日快照**,图表要等下一次 14:52 cron 才有数据点

**影响**:
- 清零后到 14:52 之前,用户看图表是空的
- 如果是非交易日清零,要等下一个交易日 14:52

**可选改进**(不算 P0 必须):
```python
# reset 后补一帧当日快照
_engine.record(date.today(), snapshot={})  # 空 snapshot,所有持仓市值为 0
```

但这要求传入 snapshot,而 cron_jobs 里 snapshot 来自 parquet。重置后立即同步今日快照需要重新加载 parquet 数据——属于锦上添花,不影响主流程。

**建议**:计划书可加一句"清零后到当日 14:52 期间,净值曲线无数据点,属正常"。

#### 二、必须实现的功能点

1. **数据加载**(断网友好)
   - 不调用 `_load_trading_calendar()`(依赖 baostock)
   - 改为:**遍历 parquet 目录,收集所有 date 字段并去重,得到完整交易日列表**
   - 对每个交易日,从 parquet 加载所有持仓候选票的收盘价,构建 snapshot 字典
   - 复用 `cron_jobs.py:417` 的 `augment_bars_with_realtime` 思路
   - ⚠️ 反推的日历可能包含一些已退市/暂停股票 → 在选股环节过滤掉

2. **逐日回放**(单 engine 持续)
   - 用一个全局 engine 实例,4 个月内不重启
   - 对每个交易日 d(从 3/1 到 7/1,跳过反推日历外的日期):
     - 调用 QUANTQQ 公式用 parquet 当日数据计算 signals
     - `engine.sell_phase(d, snapshot[d], trading_dates)` —— 触发卖出
     - `engine.execute_buy(d, code, price, strategy_name="QUANTQQ")` —— 触发买入
     - `engine.record(d, snapshot[d])` —— 记录当日净值
   - 这一天的处理逻辑与 14:52 cron 完全一致(参考 cron_jobs.py:430-509)
   - ⚠️ `_prev_day_snap` 必须**累积**,不要重置(否则除权跳空保护失效)

3. **结果输出**(隔离写入)
   - **不写入 `output/sim_trader/state.json`**
   - 写入 `output/sim_trader/imports/replay_20260301_20260701.json`(自动创建 imports 目录)
   - 生成完整的 equity_curve(从 3/1 到今天,每天一条)
   - 生成完整的 trades 列表
   - 输出每日明细到 `output/sim_trader/imports/replay_daily_log.csv`(便于人工审计),格式如下:

     ```csv
     date,equity,cash,positions,buy_count,sell_count,signal_count
     2026-03-02,1000000,1000000,0,0,0,0
     2026-03-03,1005234,505234,2,2,0,5
     ```

4. **配置开关**
   - 读取 `app.sim_trader.config` 的 `AUTO_SELL / AUTO_BUY / AUTO_SCAN` 开关,与生产 cron 一致
   - 默认用 QUANTQQ 策略(可参数化 `--strategy`)

5. **失败容忍**
   - 用 try/except 包住每一天的回放逻辑
   - 单日失败 → 写一行到 `replay_errors.log`(日期+异常类型+堆栈前 5 行),跳过当天继续
   - 连续失败计数器 `consecutive_failures`,超过 `--max-failures`(默认 3)则中断
   - 总失败计数器 `total_failures`,在最终输出中打印"X 天成功,Y 天失败"

6. **选股公式调用**(最复杂的部分)
   - 不能用历史 cron 日志(因为日志不区分"是重跑还是原 cron")
   - 必须**重新调用 QUANTQQ 公式**
   - 公式文件可能在 `app/strategies/` 或 `core/`,具体位置团队需要查
   - 调用方式:用 parquet 当日数据喂给公式,返回 signals 列表
   - 如果 QUANTQQ 公式过于复杂或不可调用,**降级方案**:用 daily_klines 简单均线交叉选股
   - 公式调用失败 → 该日选股步骤标记为 0 signals,后续 buy_phase 自动跳过(不影响 sell_phase 和 record)
