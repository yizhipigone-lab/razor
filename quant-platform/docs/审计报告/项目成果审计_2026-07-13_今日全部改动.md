## 🏛️ 架构分析师发现

### ✅ 关键澄清：停止功能不是"从零加"，是"前端接入 + 后端增强"
- **5/14（2 个月前）原作者** liuziheng 已写了 `/api/backtest/run-simple/stop` 端点（用 `if 'simple_bt' in stop_events` 模式，无 broadcast），但**前端从未接入**（用户看不到停止按钮）
- **今天（19:00~19:21）我做的事**：
  - 前端：切按钮 + 禁用配置 + 监听 `simple_bt_stopped` + 抽 `_resetSimpleBtButtons` 统一恢复
  - 后端：broadcast `simple_bt_stopped` + 改写 stop 端点（更宽松：总是返回 ok + 加 warning 日志）
- **影响**：之前用户看不到停止按钮的根本原因是前端没接，不是后端没实现

### ✅ 前后端契约一致
- 前端 `stopSimpleBacktest` fetch `/api/backtest/run-simple/stop` POST → 后端端点存在
- 后端 stopped 时 broadcast `{type: "simple_bt_stopped"}` → 前端 handleWS 监听匹配 → 恢复按钮
- 后端 `backtest_done` 监听（已完成路径）也调用 `_resetSimpleBtButtons` → 统一恢复

### ⚠️ a847ec2 commit 混入（commit hygiene 问题）
- 现象：我的停止功能前端改动被混入 `feat(live_trader): 全局买入金额边界...` commit，commit message 没提停止功能
- 后果：审计/git log 追溯时，停止功能的前端改动"隐藏"在 live_trader feat 里
- **归因**：不是我 commit 的（被别人 commit 时一并提交），但本质是 commit 卫生问题
- 影响：能跑，但 git 历史追溯不清晰

### ✅ broken 状态已修复（d4f8961）

## ⚙️ 功能分析师发现

### ✅ 按钮状态切换逻辑正确
- `_resetSimpleBtButtons()`：run 显示+enabled / stop 隐藏+enabled+重置文字 / 配置按钮 enabled / hideProgress ✓
- `stopSimpleBacktest()`：disable stop + 改"⏳ 发送中..." → fetch → 成功则后端响应 / 失败恢复 stop 按钮 ✓
- `runSimpleBacktest()` 启动：隐藏 run / 显示 stop / disable 配置 / showProgress ✓
- 完成路径（normal/stopped/error）三种都用 `_resetSimpleBtButtons` 统一恢复 ✓

### ⚠️ **HIGH — stopSimpleBacktest catch 路径按钮卡住 bug**
- 位置：[main.js:4824-4827](static/js/main.js#L4824)
- 问题：catch 分支只恢复 stop 按钮（disabled=false + 文字回"⏹ 停止回测"），**没恢复 run 按钮**（仍隐藏）
- 触发场景：后端没启动 stop 端点（404）、网络错误、后端超时
- 后果：用户点"停止"按钮 → 失败 → 按钮停在"⏹ 停止回测"状态 → **用户无法再点"开始回测"**（按钮被隐藏），必须刷新页面
- 修复：catch 应调 `_resetSimpleBtButtons()`（统一恢复）
- **严重度**：HIGH（破坏用户体验，可重现）

### LOW — 边界条件
- race condition：用户点停止时任务刚好自然完成 → stop_event 已 cleanup → `evt = stop_events.get('simple_bt')` 返回 None → 跳过 set。但前端会收到 backtest_done（自然完成）→ 按钮恢复 ✓ 可接受
- 重复点停止：第一次 disable 按钮，第二次点不到 ✓
