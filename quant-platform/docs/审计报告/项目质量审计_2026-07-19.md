## CRITICAL（7 条，必须修）

### C1 — DuckDB 单连接查询不持锁 → 并发段错误（实测可复现）
- **位置**：[store.py](app/live_trader/store.py) 全部查询方法（`get_order_by_seq`/`get_positions`/`get_position`/`get_deals`/`get_daily_baseline`/`get_equity_points` 等 14+ 个）
- **问题**：`LiveTraderStore` 用单一 `self._conn`，**写**方法持 `_db_lock`，但所有**查询**方法不加锁。store 被 callback/flusher/scheduler/API/reconciler/exit_monitor/pnl_engine 多线程调用。
- **实测**：2 写线程 + 4 读线程跑同一 connection，1.5 秒内 `Segmentation fault (EXIT=139)`——C 层崩溃，Python try/except 接不住。读也持锁后 0 错误。
- **后果**：任一查询与 flusher 写时间重叠 → live_trader 进程段错误 → **实盘中断、账目停摆、撤单/风控全失能**。违反 CLAUDE.md「别在不加锁的情况下跑并发 DuckDB 连接」。
- **修复**：所有 `self._conn.execute`（含查询）统一 `with self._db_lock:` 包裹。

### C2 — CORS `allow_origins=["*"]` + `allow_credentials=True`
- **位置**：[main.py:101-107](app/live_trader/main.py#L101)
- **问题**：FastAPI 在此组合下回显请求 Origin = 任意 Origin + 允许凭据。任何网站的 JS 都能跨域带 Cookie/Authorization 调所有写端点。`docs/全系统深度审计_2026-06-29.md` 已记录仍未修。
- **修复**：改白名单 + 保留 credentials；或 `["*"]` + `allow_credentials=False`。

### C3 — `host="0.0.0.0"` + 所有写端点零鉴权
- **位置**：[main.py:207-208](app/live_trader/main.py#L207)；写端点遍布 app/api/（仅 `/shutdown` 有 `_is_local`）
- **问题**：同局域网/外网任何人可 curl：`/api/sim-trader/reset` 清空模拟盘、`/api/factory/destroy_physical_strategy` 删策略、`/api/settings/env-keys` 写 .env 投毒 LLM、`/api/settings` 全量改配置。
- **修复**：生产绑 `127.0.0.1`；或所有 POST/PUT/DELETE 统一加 `Depends(verify_local_or_token)`。

### C4 — `/api/data/sync_log` 无鉴权 WebSocket 注入
- **位置**：[app/api/data_sync.py:72-87](app/api/data_sync.py#L72)
- **问题**：任何客户端 POST 任意 type/level/msg，`sync_broadcast` 推给所有 WS 客户端；`msg_type=='done'` 会调 `_sync_release()` 释放全局同步锁。可伪造完成信号让前端误判、或释放锁抢占正在跑的下载。
- **修复**：加共享密钥 header + 限制源 IP。

### C5 — AI 优化器头条收益用全样本呈现（过拟合自欺）
- **位置**：[ai_optimizer.py:1070,1085-1086](app/backtest/ai_optimizer.py#L1070)
- **问题**：Optuna 用 valid 选参、WFO 算 OOS 都是防过拟合措施，但最终给用户看的"最优平盈率"由 `_run_trial(top10[0], start, end)` 全样本（含 test 集）计算 → 系统性高估实盘表现。
- **后果**：用户看到的「+X%」含 test 集 IS 数字，典型"看起来能赚"。
- **修复**：头条改报 OOS/test pnl，全样本仅附注。

### C6 — AI 优化器退出语义与生产引擎不一致
- **位置**：[simulate_one_trade.py:191](app/backtest/simulate_one_trade.py#L191)（单 `check`）vs [simple_runner.py:166](app/backtest/simple_runner.py#L166)（`check_all`）
- **问题**：optimizer 委托 simulate_one_trade 用单信号 `check`；生产日线 FastEngine 用 `check_all`（TP 部分卖后同 bar 继续 trailing/止损）。优化选出的"最优参数"放进生产引擎跑会走不同退出路径。
- **修复**：simulate_one_trade 改 `check_all` 并按 ratio 累计，与 FastEngine 统一。

### C7 — API 层寄生 service 职责，域层反向依赖传输层（masked cycle）
- **位置**：[api/sim_trader.py:27/54/81/99](app/api/sim_trader.py#L27) 的 `get_engine()/_load_trading_calendar()/is_trading_day()/get_trading_dates()` 被 6 个非 API 模块反向导入；[engine.py:207](app/sim_trader/engine.py#L207) lazy-import `app.api.sim_trader`
- **问题**：纯领域/基础设施工具寄生在 FastAPI 路由模块；域层 lazy-import 传输层，靠 `try/except: pass` 掩盖循环（engine.py:208 失败静默降级为 `trading_dates=set()` → "0 个交易日"隐性错误）。
- **修复**：抽 `app/trading_calendar/service.py` + `app/sim_trader/service.py`，API 层只剩薄路由。
