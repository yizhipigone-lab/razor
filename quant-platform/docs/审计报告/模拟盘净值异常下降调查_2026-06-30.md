# 模拟盘净值异常下降调查 — 60.4 万凭空消失

**调查日期**: 2026-06-30
**调查对象**: quant-platform 模拟盘交易模块 (`app/sim_trader/`)
**现象**: 图表显示 6/26 → 6/29 净值下降 60.4 万,但交易记录无买卖

---

## 1. 用户报告

> "模拟盘,交易控制模块,6月29号,图表显示净资产减少60.4万,但是交易记录26号到29号之间,没有交易,没有看到买入卖出,这个60.4的减少,从何而来?"

## 3. 根因分析

### 3.1 不是真的"亏损"

```
不是 4 只股票亏了 60.4 万
是 4 只持仓从 positions 中消失了,但 cash 没有相应增加
```

### 3.2 嫌疑代码路径: `sell_phase` 持久化顺序

[app/sim_trader/engine.py:502-552](app/sim_trader/engine.py#L502-L549) 中 `sell_phase` 方法的清理逻辑:

```python
def sell_phase(self, today, snapshot, trading_dates):
    sells = self.check_stops(today, snapshot, trading_dates,
                             prev_snap=self._prev_day_snap)

    for pos, exit_price, reason, partial in sells:
        trade = self.execute_sell(pos, exit_price, reason, partial,
                                  exit_date=today, exit_timing="close")
        # ... broker 部分 ...

    # 清理已平仓
    self.positions = {k: v for k, v in self.positions.items() if v.is_active}
    self._prev_snap = {k: dict(v) for k, v in snapshot.items()}
    self._prev_day_snap = copy.deepcopy(self._prev_snap)

    if self._store:
        self._store.save_prev_day_snap(self._prev_day_snap)
        self._store.save_positions(self.positions)  # ← 此时写入"清理后"的位置
        self._store.save_state(
            self.cash, self.consecutive_losses,
            self.pause_until, self._trade_count)
```

### 3.3 最可能的发生场景

按 6/26 数据推断,事件序列:

| 步骤 | 内存状态变化 | 文件持久化 |
|------|------------|-----------|
| 1. 14:52 sell_phase 触发 4 只止盈止损 | cash → ~3,597,708, positions → 空 | 无 |
| 2. `_today_trades` 累计 4 笔 | trades += 4 | 无 |
| 3. `self.positions = {k:v for ... if is_active}` | positions = {} | 无 |
| 4. **进程在写入前被强杀** (重启/异常/中断) | — | 无 |
| 5. 下次启动,`_fill_missing_snapshots` 读不到完整快照 | — | — |

**结果**:
- 6/29 14:52 cron 触发模拟盘,加载 `state.json`:
  - `cash` = 2,993,729 (旧值,6/26 14:52 之前的现金)
  - `positions` = {} (旧值,6/26 14:52 已清理,但没保存新 cash)
  - `_today_trades` 漏掉 4 笔卖出
- `record()` 写入 6/29 净值 = `cash + 持仓市值` = `2,993,729 + 0` = `2,993,729`
- 曲线从 3,597,708 → 2,993,729,差额 60.4 万被永久"记账"

### 3.4 第二个嫌疑: JsonSimStore 无事务

[app/sim_trader/store.py:229-337](app/sim_trader/store.py#L229-L337) 中 `JsonSimStore`:
- 用 `self._data` 内存 dict + JSON 文件落盘
- `save_positions` / `save_trade` / `save_state` **没有事务包装**
- `execute_sell` 内部连续调用 3 次 save,任何一个中途异常都会导致状态错位

```python
# engine.py:489-494
if self._store:
    self._store.save_trade(trade)
    self._store.save_positions(self.positions)
    self._store.save_state(
        self.cash, self.consecutive_losses,
        self.pause_until, self._trade_count)
# ← 这 3 行任意一行失败,数据已不一致
```

## 4. 证据链总结

| 证据 | 指向 |
|------|------|
| 6/26 → 6/29 现金完全相同 (2,993,729) | 没有卖出交易发生 |
| 6/26 → 6/29 持仓数从 4 → 0 | positions 被清空 |
| 6/26 → 6/29 净值差额 = 4 只持仓市值 | 消失的恰好是这 4 只股票 |
| `trades` 表中 6/26 之后 0 笔 | 卖出日志缺失 |
| `sell_phase` 持久化顺序在清理 positions 之后 | 中断即可造成此现象 |
| `JsonSimStore` 无事务 | 写一半中断会导致数据错位 |

---

## 5. 修复方向

### 5.1 立即可做:手动补数

通过 DuckDB 查 parquet 历史数据,确认 6/26 那 4 只持仓的实际成交价,反推卖出:
- `data/parquet/daily/{code}.parquet` 取 6/26 close
- 计算 4 只的应收回现金 = cash 应到 ~3,597,708
- 补写 4 笔 trade 记录 + state.json 修正

### 5.2 短期:加交易日幂等

[app/scheduler/cron_jobs.py:387-507](app/scheduler/cron_jobs.py#L387-L507) 中已有 `_daily_ran_date` 防重,但:
- 只防同日重复,不防 sell_phase 半完成
- 重启后 `_daily_ran_date` 不会清,6/27 重启后认为 6/26 已跑,跳过补数

加一个"启动时校验 equity_curve 连续性"的钩子:发现曲线断层 + cash/positions 不匹配,自动告警或回滚。

### 5.3 中期:写顺序调整 + 事务

[app/sim_trader/engine.py:502-552](app/sim_trader/engine.py#L502-L549) 改为:

```python
def sell_phase(self, today, snapshot, trading_dates):
    sells = self.check_stops(...)

    # 1. 先在内存执行卖出
    for pos, exit_price, reason, partial in sells:
        trade = self.execute_sell(...)  # cash/positions 已更新

    # 2. 一次性持久化完整状态(原子的"快照写入")
    if self._store:
        self._store.atomic_save({
            'positions': self.positions,
            'cash': self.cash,
            'consecutive_losses': self.consecutive_losses,
            'pause_until': self.pause_until,
            'trade_count': self._trade_count,
            'prev_day_snap': self._prev_day_snap,
        })

    # 3. 才清内存中的已平仓位置
    self.positions = {k: v for k, v in self.positions.items() if v.is_active}
```

`JsonSimStore.atomic_save()` 用 `tempfile + os.replace` 实现原子写。

### 5.4 长期:DuckDB 替代 JsonSimStore

线上环境用 `SimTraderStore` (DuckDB),DuckDB 自带事务:
- `BEGIN` / `COMMIT` 包裹 sell_phase 的所有写入
- 进程崩溃可回滚到上一致状态

但当前 API `get_engine()` 在 [app/api/sim_trader.py:27-46](app/api/sim_trader.py#L27-L46) 强制用 `JsonSimStore()`,需要先调研为什么不用 DuckDB,再决定是否切换。

---

## 6. 总结

**核心结论**: 60.4 万不是亏掉的,是 4 只持仓的卖出在 `sell_phase` 执行过程中被打断,导致 cash 没更新但 positions 已被清空,造成现金和持仓的"账实不符"。

**严重程度**: 中等 — 数据完整性 bug,但不是策略亏损。
**影响范围**: 净值曲线 + 收益统计失真,但实际无资金损失。
**修复优先级**: 高 — 应在下次 sell_phase 触发前修复,否则类似情况会再次发生。
