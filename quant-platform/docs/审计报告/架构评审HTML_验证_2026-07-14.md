## 两处硬错误详述(动工前必读)

### ❌ 错误 1:CARD 2 主张 4 —— "THSGateway 签名 incompatible"

报告原文:"THSGateway incompatible sig",mermaid 图标 `THS["THSGateway\nincompatible sig"]`。

**真实代码(逐字对比)**:
```python
# app/trader/gateways/qmt.py:41
def buy(self, code: str, price: float, volume: int = None, reason: str = "手工买入") -> bool:

# app/trader/gateways/ths.py:42
def buy(self, code: str, price: float, volume: int = None, reason: str = "手工买入") -> bool:
```
两边 buy/sell 签名**完全相同**。报告这条论据用错了。

**真正的不兼容在别处**(结论"两个 gateway 不可互换"仍成立):
- `connect()`:QMTGateway 声明 `-> bool` 且 return True/False;THSGateway 无返回注解、无显式 return(隐式 None)
- 方法集不同:QMTGateway 多了 `get_live_trader_quotes/get_stock_list/get_index_members/cancel_order`,THSGateway 没有

### ❌ 错误 2:CARD 3 主张 1 —— 暗示 "MyTT 有 ATAN 实现"

报告 mermaid 图:`MYTT["MyTT\nMA · CROSS · ATAN · …"]`,把 ATAN 列为 MyTT 已有能力,然后批评策略"绕过它手写 arctan"。

**真实代码**:`app/indicators/MyTT.py` Grep 结果只有 SIN/COS/TAN(L28-30),**唯独没有 ATAN**。全项目多处注释明确写"MyTT 无 ATAN":
- `app/indicators/user_formulas/ma5_angle_signal.py:47`:`# (MyTT无ATAN,用np.arctan)`
- `app/strategy_factory/translator.py:43`:`# ATAN: MyTT 无,映射到 np.arctan`
- `tests/test_translator.py:96`:`"""ATAN → np.arctan (MyTT 无 ATAN)"""`

即:策略手写 arctan 的**根因正是 MyTT 缺 ATAN**,而不是"有却绕过"。改进建议(给 indicators 加 grouped-DataFrame ATAN 变体)方向对,但报告的"现状描述"反了。

**额外发现**(报告漏的):MA5-angle 实际有 **4 处**实现,不只 3 处——`app/data_manager/tushare_api.py:149` 还用 `SLOPE` 算了一版变体。

## 给动工者的建议

1. **可放心做的(高可信、论据扎实)**:CARD 1、CARD 4、CARD 5、CARD 6。这四张卡文件/行号/公式全部对得上,改进方向成立。
   - 其中 **CARD 4(今日盈亏)是最扎实的一张**——5 条全 PASS,行号精确,前端还额外暴露出"两套不同算法"的隐藏问题。
   - **CARD 1 是最高杠杆**——"4 引擎不可比"是已记录的系统风险,execution.py 只给 rates 不给 P&L fold 是确凿的机制根因。

2. **要做但先修措辞的**:
   - **CARD 2**:别照"签名不兼容"去改(签名本来就一致);真问题是无 Protocol 契约 + buy/sell 是 stub + 真实下单绕过 gateway。改的方向(OrderGateway Protocol + DryRun 适配器)对。
   - **CARD 3**:别假设"MyTT 有 ATAN 被绕过";正确表述是"MyTT 缺 ATAN,导致 4 处各自手写"。改进(给 indicators 补 ATAN + grouped API)仍值得做。

3. **also-noted 优先级**:D(hot_sector 假零,真·假默认值风险,已记入 known_risks)和 A(sim_params 双写)值得优先收;B 的框架描述要更新(strict 已删)。
