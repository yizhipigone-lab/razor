## 1. 项目基础背景与初始目标

### 1.1 触发起点

本次整改最初由一个具体 bug 触发，随后扩展为全项目质量审计与系统性整改：

| 阶段 | 触发内容 |
|---|---|
| 起点 bug | 回测面板调 TP1（3%→2.5%）/ 增加止盈档位，刷新或重启后回退默认值；点「系统配置」无反应 |
| 扩展 1 | 用户要求全维度质量专项审计（8 大维度） |
| 扩展 2 | 引入两份第三方大模型评估 + 交叉验证 |

| 收尾 | 数据层全库补列 + 前端指标复权调查 + 推送远程 |

### 1.2 整体工作范围（8 大审计维度 + 专项修复）

| 维度 | 覆盖内容 |
|---|---|
| 回测精度 | Python 策略 / 通达信公式双体系、信号无漂移、收益/回撤/盈亏指标计算 |
| AI 参数寻优 | 拉丁超立方采样、市场状态分区、参数空间搜索、过拟合风险 |
| 代码工程质量 | 逻辑连贯性、功能完整性、边界鲁棒性、异常捕获、注释规范 |
| 前后端数据一致性 | 后端计算 ↔ 前端展示 ↔ 指标数值三者对齐，隐形渲染偏差 |
| 数据同步机制 | 自动同步配置、数据补全、时间戳对齐、缺失容错 |
| 模拟盘核算精度 | 账户总资产、持仓市值、单笔/累计盈亏、手续费滑点 |

### 1.3 原有系统的底层风险（审计前已知 + 审计暴露）

会话起点已记录于项目 memory 的既有风险：

| 既有风险 | 说明 |
|---|---|
| 假默认值 | 配置缺失时静默使用硬编码默认值下单 |
| AI 过拟合 | in-sample 优化后直接当结论 |
| 实盘买入不下单 | 模拟盘日切标志问题 |
| 4 引擎不可比 | engine/simple/tdx/strict 的成本/T+1/涨停各写各的 |
| config 非唯一真相源 | 参数链路 config→前端→引擎可能断裂 |

### 1.4 业务影响

1. **回测收益系统性高估** → AI 寻优在错误前提上选参 → 实盘必然衰减。
2. **参数无法持久化** → 用户调参白费，重启回退。
3. **模拟盘账务失真** → 零成本核算使净值/胜率/盈亏比全部偏乐观。
4. **数据口径分裂** → 除权日价格跳空污染所有基于涨跌幅/止损百分比的信号。
5. **静默失败** → 异常被吞、数据缺失被掩盖，运维无法察觉。

## 2. 多轮研讨与方案迭代全过程

本次最大特点是**多轮对抗式交叉验证**，结论经过 4 份报告 + 用户 2 次指正反复迭代。

### 2.1 第一轮：起点 bug 的系统化调试

**原始思路**：用户报"调 TP1 刷新回退 + 系统配置按钮无反应"，直觉是保存接口问题。

**调试过程（systematic-debugging）**：追踪「保存 → 持久化 → 加载」全链路，发现两个独立根因：

| Bug | 根因 | 定位 |
|---|---|---|
| #1 调参刷新即还原 | 自动加载函数 `loadBtSimpleConfig()` 在读取前先 `POST /simple-config/reset`，用硬编码默认值**覆盖落盘**了用户保存的配置文件 | `main.js:3953`（旧） |
| #2「系统配置」按钮无反应 | `_default_bt_config()` 只读 `sim_trader/config.py` 纯硬编码常量，从不读 `app_setting.json` | `backtest.py:508` |

**思路修正**：用 AskUserQuestion 确认两个决策点后定方案——
- 决策 1：回测配置**完全独立**持久化（非镜像系统设置）
- 决策 2：「系统配置」按钮 = **手动从系统设置拉取覆盖面板**

**方案**：拆分混在一起的"自动加载"与"拉取系统值"，移除自动加载里的 reset 调用；`_default_bt_config` 改为读 app_setting。

### 2.2 第二轮：全维度审计（6 个并行 agent）

**思路**：8 维度高度耦合，把「前后端一致性 + 可视化 + 隐性缺陷」三项合并给一个 agent（避免三个 agent 各读同样文件出割裂结论），其余维度独立。共 6 个并行只读审计 agent。

**产出**：审计报告 76 项问题（17 CRITICAL / 22 HIGH / 23 MEDIUM / 14 LOW）。

**交付决策**（AskUserQuestion）：用户选「出报告 + 修复 CRITICAL」「深度全覆盖」。

**首轮修复**：仅修 3 项无副作用的纯 bug（模拟盘日切、min5 import、tdx trades 翻倍）；其余设计性失真留待决策。

### 2.3 第三轮：三方交叉验证（争议焦点 = 成本归属）

引入两份第三方评估，三方在"问题清单"高度一致，但在**成本到底在哪条路径扣/不扣**上互相打架。

**争议点**：
- 我原报告说"四引擎全零成本""唯一扣成本的 `_simulate_trade_v2` 是死代码"
- 评估 A 纠正"FastEngine/StrictEngine 实际扣成本"，但自己 §2.3 又说"simple 日内/tdx 全程零成本"
- 评估 B 抓出评估 A 的自相矛盾

**裁定方法**：我不当裁判复读，逐路径 grep+Read 建立**成本真相矩阵**：

| 仿真路径 | 触发条件 | 扣成本？ |
|---|---|---|
| BacktestEngine `_simulate_trade_daily_fallback` | engine.run() 唯一实际路径 | ❌ 不扣 |
| BacktestEngine `_simulate_trade_v2` | 5m，但 freq 写死 daily | ❌ 死代码 |
| simple_runner/FastEngine（日线） | intraday_freq=daily | ✅ 扣 |
| simple_runner/`_run_intraday_backtest`（5m/1m） | intraday_freq∈{5m,1m} | ❌ 不扣 |
| strict_runner | 严格模式 | ✅ 扣 |
| tdx_runner 日线分支（FastEngine） | TDX+daily | ✅ 扣 |
| tdx_runner `_run_intraday_backtest`（5m/1m） | TDX+5m（默认） | ❌ 不扣 |
| ai_optimizer `_fast_simulate`（1m） | AI 寻优 Python 策略 | ❌ 不扣 |
| sim_trader/SimTraderEngine | 模拟盘 | ❌ 不扣 |

**自我认领的 2 处错误**：①"四引擎全零成本"不准确 → 改成本真相矩阵；②"唯一扣成本死代码"应限定为「BacktestEngine 体系内」。统计笔误 75→76（LOW 是 14）。

**对评估的反向评价**：评估 A 自相矛盾（B 抓得对）；评估 B 数据层 C1/C3/C4 全标"未核实"就放过——我替两方补刀：数据-C1（min5 列名分裂）经核实**真实成立、CRITICAL 维持**。

### 4.1 【HIGH】0.83% 边界陷阱（P0-1 阶段）

## 7. 整体风险总结与沉淀规范

### 7.1 暴露的系统架构短板

| 短板 | 表现 | 教训 |
|---|---|---|
| 多引擎口径分裂 | 4+ 仿真路径成本/T+1/涨停各写各的 | 共享执行层（execution.py）应是唯一入口 |
| 写入/读取层职责混乱 | 指标在写入算、复权在读取做 → 潜在错位 | 同一数据变换应在同一层 |
| 单位约定无中心定义 | profit_pct 两引擎约定相反 | 需 schema 级单位契约 |
| 静默失败遍地 | except: pass/continue 吞异常 | 金融系统禁止静默吞错 |
| 假默认值 | 配置缺失静默用硬编码 | fail-fast，不用假默认 |
| 死代码伪装 | _simulate_trade_v2 扣成本但从不被调 | 死代码误导维护者判断 |

### 7.2 研发流程漏洞

| 漏洞 | 改进 |
|---|---|
| 改动无基线对比 | 改历史结果的改动必须 tag+备份+基线 diff |
| 缺验证就声称完成 | 每步独立脚本验证，evidence before assertion |
| "顺手改"破坏下游 | 改前 grep 所有调用方，跨多点的改动升级为正式任务 |
| 报告措辞不精确 | 用代码核实而非表面说法，建"真相矩阵"裁定分歧 |

### 7.3 后续标准化约束规则（沉淀）

1. **修改铁律**：绝不因新增/修改影响已有功能；改前盘点引用、保留旧路径、独立新文件优先、改后跑最相近测试、备回滚预案。
2. **单位契约**：config 与内部传递一律小数；转换只在边界；禁止启发式猜测单位。
3. **成本/口径**：所有成交走 execution.py；成本率进 config 禁硬编码；各引擎口径差异需文档固化。
4. **数据层**：写同目录必须同 schema；增量同步做断档检测；复权在读取层归一，存原始价+因子。
5. **异常处理**：不静默吞错，至少 log.error(exc_info=True)；配置缺失 fail-fast。
6. **验证**：改历史结果的改动 tag+备份+基线 diff；每步语法校验+逻辑脚本验证；test 集严格隔离。
7. **AI 寻优**：objective 在样本外（valid）爬山；最终选优口径与中间排序一致；样本按自然日切；目标函数含风险惩罚+最小样本门槛。
