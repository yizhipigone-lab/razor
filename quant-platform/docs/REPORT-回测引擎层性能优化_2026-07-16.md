# 回测引擎层性能优化 — 工作成果报告

> 日期: 2026-07-16
> 范围: TDX 日线回测 + Python 策略回测(共用引擎层)
> 原则: 零差异提速(回测数字一模一样)/ 不碰缓存(重启不重建)

---

## 一、背景与起因

用户反馈"回测感觉变慢",怀疑是代码变更导致。排查发现**两个独立问题**:

1. **崩溃(已修)**:`tdx_runner.py` 逐日回放循环引用了一个未定义的变量 `prev_day`(从日内循环误拷贝到日线循环),导致 TDX 日线回测一遇买入信号就 `NameError` 崩溃。这是用户看到"跑到逐日回放就停住、出不来结果"的直接原因。7.15 提交 `b613d6d`(涨停过滤功能)引入,7.14 版本无此问题——这解释了"以前的版本更好用"。
2. **性能仍有提升空间(本次工作)**:三路深度代码分析(FastEngine 主循环 / TDX 取数 / 数据解析)确认瓶颈都指向同一病根——**全程不变的东西被每天/每行/每笔重算**。

本次工作聚焦第 2 项的**引擎层与解析层**优化,一个字未碰 TDX 取数(worker)和缓存 key 逻辑。

---

## 二、目标与约束(用户确认)

| 项 | 约定 |
|---|---|
| **正确性** | 回测数字零差异(基线 diff 验证,逐字段一致) |
| **范围** | TDX + Python 两条路径都优化(改共用层即两条都覆盖) |

## 四、改动明细(5 项,均零差异验证)

改动集中在三条路径共用的引擎层,故 TDX 和 Python 两条回测同时受益。

| 编号 | 文件 | 改动 | 收益层级 |
|---|---|---|---|
| **A** | `exit_rules.py` / `simple_runner.py` | `build_context` 把 ~20 个整场不变的风控参数一次性预解析(新增 `precompute_params`),`FastEngine.__init__` 算一次复用。原先每持仓每天重建 35 字段对象、重取 30 次 `params.get` | 逐日回放主热点(量级 天数×持仓) |
| **B** | `execution.py` / `simple_runner.py` | 成本配置在 `__init__` 缓存一次(`self._cost_cfg`),`buy`/`sell` 复用。原先每笔交易重建字典 + import settings | 每笔交易 |
| **C2** | `tdx_runner.py` | 消除信号值 `_is_signal_value` 的双重解析(解析时只存"确为信号"的日期,`pending_buys` 不再二次判定) | 数据解析 |
| **D** | `tdx_runner.py` | 修 `low_cache` 的 O(N²) 重复读盘隐患:缓存粒度从 `(日期,股票)` 改为按股票缓存整只 low 映射;`has_ohlc` 改逐行判断,不再让一行脏数据把整只股票永久打到 parquet fallback | 防雷(平时不触发,触发时灾难性) |
| **E** | `tdx_runner.py` / `simple_runner.py` | 热循环去掉不必要的 `list()` 拷贝(每天一次 O(持仓数));`exit_rules` 的 import 从函数体提到模块顶层 | 累积小优化 |

### 各项零差异实测记录
- A: 14.54s → 12.34s ✅ 零差异
- B: → 12.62s ✅ 零差异
- C2: → 10.92s ✅ 零差异
- D: → 11.03s ✅ 零差异(fallback 未触发,数字不变,隐患已除)
- E: → 10.96s ✅ 零差异

## 五、为什么保证零差异

每项改动的本质都是"把重复计算改成算一次复用",取值逻辑与默认值完全照搬原代码:

- **A**:`precompute_params` 用与原 `build_context` 逐一对齐的 `.get(key, same_default)`;参数整场不变,预算一次 == 每次算。
- **B**:`get_cost_cfg()` 整场返回同一份(settings 不变),提前算一次结果字节一致。
- **C2**:只是把"存所有日期再二次过滤"改为"解析时一次过滤",信号集合不变。
- **D**:正常路径(现代 worker 带完整 OHLC)本就不走 fallback;触发时读同一 parquet,low 值一致。
- **E**:去掉的是只读迭代的防御性拷贝,不改数据。

验证兜底:临时基线脚本对 summary + 排序后 trades + equity 逐字段 diff(float 容差 1e-6),任一差异即拦截并回退该项。全部通过。

## 七、遗留问题(独立于本次,需另行排查)

**TDX 日线回测涨停过滤大面积降级**:验证时日志出现大量 `buy() 缺 prev_close ... 涨停过滤降级`。根源是早先修 crash 时用 `td_list[d_idx-1]` 取前一交易日收盘价,但前一交易日的 snap 里常常没有该股数据(停牌/当天首次出现在信号中),导致 `prev_close` 取不到、涨停过滤退回"无过滤"路径。

- **对本次优化无影响**:改前改后都是这个行为,回测数字一致。
- **是独立的正确性问题**:值得单独立项排查前收的正确取法。

## 八、后续计划(第二步,待用户发话)

**缓存层增量化**(高收益、高风险,需独立计划 + 充分测试):
1. 消除 TDX "取两遍数据"(扫信号已读过日线,又用 get_market_data 重取一遍 OHLC)
2. 增量缓存(现在改一天区间就整池 897 万行全重取)

这两项占总耗时一大半,但会改动 worker/缓存 key,升级时需一次性重建缓存(之后长期不再重建)。
