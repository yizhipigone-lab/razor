## 1. 回答你的问题：他说的「未跑 78 公式基线 diff」具体指什么

**意思**：P0-1 改动了 `engine.py`（v2 的 `tp_pct / 100` 改为直接乘小数）和 `ai_optimizer.py`（`_fast_simulate` 的 tp_pct 单位转换），这会**改变历史回测的止盈触发时机**。

具体影响：

| 改动 | 修复前 | 修复后 | 对回测结果的影响 |
|---|---|---|---|
| v2 `tp_price = entry*(1+tp_pct/100)` | tp_pct=0.027→`/100`→+0.027%触发 | `entry*(1+0.027)`→+2.7%触发 | **止盈延迟**，持仓周期变长，收益变化（正或负取决于行情走势） |
| `_fast_simulate` 同 | 同上 | 同上 | Python 策略寻优的目标函数 pnl 变化 |

因为 `scripts/run_backtest.py` 调用 engine.run()，任何策略（包括 78 个 TDX 公式中走 engine 路径的）都可能受影响。**基线 diff 就是改前 vs 改后的回测结果对比**，用以确认：

1. 收益变化是否符合预期（不应有意外崩跌）
2. 止盈触发时机是否正确（+3% 触发而非 +0.03%）
3. 没有引入新的报错

## 2. 单位约定盘点文档评估

### 2.1 分析质量

**这是该项目 stop 参数单位的权威文档。** 核心突破在于区分了 **两条 stop 判定引擎**：

| 引擎 | 调用方 | 约定 | 是否有 bug |
|---|---|---|---|
| exit_rules.py 链（`rule_take_profit` -> `target=entry*(1+tp_pct)`） | simple/strict/sim_trader | **小数**（0.03=3%），与 config 一致 | ✅ 无 bug，不要动 |
| engine.py daily_fallback + `_fast_simulate` | BacktestEngine + AI 寻优 | **百分比**（`tp_pct/100`），读 config 小数值会误触 | ❌ BUG 根因 |

**这个区分解释了为什么用户长期使用 simple/strict 路径可能没感知到 bug**——exit_rules 链本来就是对的。只有走 engine.py 的 daily_fallback 和 `_fast_simulate` 才会触发。

hard_stop/breakeven 系列因 `_pct()` 自适应函数暂安全，标注为"观察项，不在 P0 动"——正确的边界控制。

## 3. 代码实现逐项核查

### 3.1 P0-1：api/backtest.py（ai/apply 写入端）

```python
def _to_decimal_pct(v):
    return float(v) / 100.0
```

**请注意**：这是**无条件 /100**。不是最早的 `if v>1 then /100 else pass`。

**为什么对**：`search_space.tp1_profit` 的值来自 `app_setting.json` 的 `optimizer.search_space`——min=0.83, max=5.52。这些是**百分比格式**（0.83=0.83%），即使 0.83<1 也要除 100 写成 0.0083=0.83%。如果用 `if v>1` 防御，0.83 会被误判为小数，写成 83%。

作者在执行报告里明确提到了这个发现——"我最初的 v>1 才除防御式判断会误当小数"——这是**执行过程中自我发现的陷阱并纠正了**。

### 3.2 P0-1：engine.py（v2 + daily_fallback）

## 4. 值得注意的问题（3 项，不影响通过）

### 4.1 saveGatewaySettings 字段不完整

`saveGatewaySettings()` 只保存了 `qmt_path` 和 `qmt_market_mode`，但系统设置 tab 的网关卡片可能还有更多字段（如 `active_gateway`、`account_id` 等）。如果 HTML 里有其他网关字段，改了不会通过总按钮保存。这不会破坏现有功能（本来这些字段就没法保存），但属于"功能补齐程度"问题。

### 4.2 `_fast_simulate` 的 P0-1 修复附带名义收益修复 — 边界有风险

engine.py L936-940 把 `tp_pct * actual_sell` 改成了真实成交价 PnL，这是**回测-C2 的部分修复**，不属于 P0-1 的"纯单位归一化"。虽然逻辑正确，但如果还有依赖旧 `realized_pnl` 路径的其他代码，会受影响。`_fast_simulate` 的 L644 保持了百分比尺度（`tp_pct * 100 * actual`），与 close_pnl 口径一致 — 正确。

整体风险低，但标注为"P0-1 顺带修了回测-C2 的部分"让后人能追溯。
