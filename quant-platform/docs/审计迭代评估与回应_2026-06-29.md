**审计声明**：BacktestEngine 的 daily_fallback / v2 用类内硬编码 `TRADE_COST_BUY=0.125/SELL=0.175`，未调 `calc_buy_cost/calc_sell_revenue`（虽 import 了）。

**我的核实**：
```
engine.py:657  cost_entry = entry_price * (1 + self.TRADE_COST_BUY / 100)  ← 类常量
engine.py:662  cost_sell = raw_sell_price * (1 - self.TRADE_COST_SELL / 100) ← 类常量
engine.py:24   from ...execution import calc_buy_cost, calc_sell_revenue   ← import 了但没用
```
**完全属实**。我任务一给 daily_fallback 加的 `_cost_pnl` 基于类常量，不是 execution.py 的函数。后果：`TRADE_COST_BUY/SELL` 是**比例**（0.125%/0.175%），与 execution.py 的成本率数值上接近但**绕过了 min_commission（5元最低）**，且不从 config 读 → engine 路径的成本率改 config 不生效。

### 1.4 🟡 澄清 + 部分接受：_fast_simulate "未统一到小数"（审计 HIGH）

**审计声明**：报告称"比较与成交价均按小数口径"，但 `realized += tp_pct*100*actual` 是把小数强行 ×100 反推回百分比，line 674/685/693 仍是百分比 → 未真正统一。

**我的核实**：
```
ai_optimizer.py:658  realized += tp_pct * 100 * actual   ← tp_pct小数, ×100 转百分比
ai_optimizer.py:674  realized += curr_stop * remaining   ← 百分比
ai_optimizer.py:685  realized += close_pnl * remaining   ← 百分比 (close_pnl=(c/e-1)*100)
ai_optimizer.py:710  realized -= (...)*100               ← 成本, 百分比
```
**事实**：`realized` 全程是**百分比口径**（所有累加点都是百分比），最终 `pnl_pct=round(realized,4)` 输出百分比——**内部自洽，无 bug**。

**澄清**：审计说我报告称"统一到小数"——但我报告 line 248 原话是「realized**×100 对齐百分比**」，我明确写了 realized 是**百分比**口径。"比较与成交价按小数"指的是 `tp_pct` 本身和 `(high/entry-1)>=tp_pct` 比较是小数——这部分确实是小数。所以：**`tp_pct` 小数 + realized 百分比，是两个不同变量的不同口径，各自自洽**，不是"未统一的混乱"。

**部分接受**：审计的措辞批评有合理性——"统一到小数"这个表述容易让人以为 realized 也是小数。**我的代码注释（ai_optimizer.py:637「比较与成交价均按小数口径」）措辞不够精确**，应改为"tp_pct 与触发比较按小数；realized 保持百分比口径"。这是注释精度问题，不是计算 bug。
