### 2.4 性能与数据流审计（agent #4）

#### 🔴 HIGH — `bars[code]==code` 全表过滤在循环内（O(N×M)）

**位置**: [engine.py:265, 275](app/backtest/engine.py#L265#L275)

```python
# 在每条信号循环中：
prev = bars[(bars["code"] == code) & (bars["date"] < signal_date)]
stock_daily = bars[bars["code"] == code]
```

**影响**: 5000股 × 2500信号 = 12.5M 行扫描，O(N×M) 复杂度。占 78 公式 6+ 小时瓶颈的 **~40%**。

**修复**: 在循环外做 `bars_grouped = dict(tuple(df.groupby("code")))` 或 `groupby().groups`，然后 O(1) 查表。

#### 🔴 HIGH — DuckDB 连接缺 `read_only=True`

**位置**: [duckdb_manager.py:99](database/duckdb_manager.py#L99)

```python
self._local.conn = duckdb.connect(str(DB_PATH))  # ← 读写连接
```

`PROJECT_RULES.md` 明确要求"盘中高频时段 API Server 应 read_only=True"。整改报告 6.x 提到 "DuckDB 被服务占用" 即此根因。

**修复**: `duckdb.connect(str(DB_PATH), read_only=True)`，写入路径专用独立连接。

#### 🟠 HIGH — TDX trial 每次重启 TDX 子进程 + 重算信号

**位置**: [ai_optimizer.py:451-489](app/backtest/ai_optimizer.py#L451-L489) + [bridge.py:236-280](app/tqsdk/bridge.py#L236-L280)

TDX 模式每次 Optuna trial 调用 `run_tdx_backtest()` → `bridge.execute_screen_range()`，启动 subprocess + TdxBridge worker 重新计算**与参数无关的信号**。50 次 Bayesian trial = 50 次完整 worker 调用。

**影响**: TDX 模式单 trial 10s → 100s；50 trial = ~80 分钟额外耗时。

**修复**: Phase 1 已为 Python 模式缓存 signals（`_cached_signals`），TDX 模式缺失同样缓存。

#### 🟡 MEDIUM — 信号过滤 `apply(lambda r: ..., axis=1)`

**位置**: [engine.py:233](app/backtest/engine.py#L233), [ai_optimizer.py:400](app/backtest/ai_optimizer.py#L400), [screener/engine.py:292](app/screener/engine.py#L292)

`axis=1` apply 逐行调用 Python lambda，5000 行慢路径。

**修复**: `signals.merge(eligible_df, on=['date','code'], how='inner')` 或 `(signals['date'].astype(str)+signals['code']).isin(set_strings)`。

#### 🟡 MEDIUM — `signals.iterrows()` 慢遍历

**位置**: [engine.py:244, 678, 902](app/backtest/engine.py#L244#L678#L902) + [simple_runner.py:302, 409, 695](app/backtest/simple_runner.py#L302#L409#L695)

`iterrows()` 比 vectorized 或 `itertuples()` 慢 5-10×。

#### 🟡 MEDIUM — 探索期 trial 重复跑 valid/test 全样本

**位置**: [ai_optimizer.py:1110-1115](app/backtest/ai_optimizer.py#L1110-L1115)

12 探索 trial 后又重跑 valid+test 各 12 次 = 36 次冗余 trial（每 trial 4 秒 = 144s 浪费）。
