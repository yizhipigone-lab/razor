## 2. CRITICAL 发现（5 条，必须立即修）

### 🔴 2.1 live_trader C1：真实成交持仓永不更新（已交叉验证）
**文件**：[callback_handler.py:326,358,365](app/live_trader/callback_handler.py) + [store.py:319-324,370-376](app/live_trader/store.py)

`_handle_trade` 先 `sync_terminal_write("deal")` 把成交写入 `live_deals` 表，**随后**才调 `apply_sell_fill/apply_buy_fill(trade_id=...)`。而 apply_*_fill 的幂等检查 `SELECT 1 FROM live_deals WHERE trade_id=?` 必然命中刚插入的 deal → `return` 早退 → **volume / can_use / peak_price / tp_triggered / entry_date 永不更新**。

- **归因**：commit 898d778（PR #6 "H1 幂等修复"）引入回归。mock 路径 `_release_pending_buy` 不传 trade_id 跳过检查 → 测试通过、实盘失效，隐蔽性强。
- **影响**：真实买入后本地持仓不变、真实卖出后不递减、清仓重置（peak/tp_triggered/avg_cost 复位）不执行 → 再买同票用旧成本/旧档位。对账器（09:35/11:30/14:55/15:05）能周期纠正 volume，但 tp_triggered/peak 复位丢失永久。
- **修复**：`live_deals` 加 `position_applied BOOLEAN DEFAULT FALSE` 列，apply 时 `WHERE trade_id=? AND position_applied=FALSE` 原子更新（顺序无关、并发安全）；或调换顺序先 apply 再写 deal。

### 🔴 2.2 live_trader C2：废单当成交，反向膨胀持仓
**文件**：[callback_handler.py:434-435](app/live_trader/callback_handler.py) → [store.py:357-407](app/live_trader/store.py)

`_handle_order_error` 处理废单（status=57）时调 `_release_pending_buy` → `apply_buy_fill(trade_id=None)` 跳过幂等 → `volume += filled_volume`。**废单=零成交，本应只释放 pending_buy_volume 冻结额，却把整单股数加进持仓**。
- **修复**：新增 `store.release_pending_buy(code, volume)` 仅释放冻结，废单路径改调它，不复用 apply_buy_fill。

### 🔴 2.3 live_trader C3：`self.audit` 未注入，DB 写失败兜底崩溃
**文件**：[callback_handler.py:329,368](app/live_trader/callback_handler.py) vs `__init__:29-37` + [main.py:138](app/live_trader/main.py)

`CallbackHandler.__init__` 无 `audit` 形参，构造处未传。但 `_handle_trade` 的 deal 写入失败分支 `if self.audit:` → `AttributeError` → 后续 `notify.send`/`apply_sell_fill`/`clearance_lock.release`/通知全部跳过，异常上抛到 xtquant callback 线程。**H3（2026-07-14 专门做的"DB 写失败不静默吞"兜底）在最该生效的场景反手崩溃**。
- **修复**：`__init__` 加 `audit=None` 形参并注入；main.py:138 构造时传 audit 实例。

### 🔴 2.4 api C1：API 密钥明文泄露
**文件**：[app/api/system.py:75-89](app/api/system.py)

`/api/settings/env-keys`（GET，无认证）返回体同时含 masked 和**完整明文** `tushare_key`/`deepseek_key`（line 84,87）。任何能访问服务者直接拿到完整 API Key。
- **修复**：删除明文两行，只返回 masked；所有写设置端点加认证。

### 🔴 2.5 config C1：飞书 webhook 已提交进 git 历史
**文件**：[config/app_setting.json:223](config/app_setting.json)

飞书自定义机器人 webhook URL（含 token）+ `gateway.account_id`/`qmt_account_id`（line 135-137）在 git 跟踪的 `app_setting.json` 里。**直接违反 CLAUDE.md 实盘备忘"飞书 webhook 在 app_setting.json 别 commit"**。即使现在删文件，token 仍在 git 历史。
- **修复**：① 立即飞书后台作废该 webhook 生成新的（已泄漏 token 无法靠改文件撤销）；② `app_setting.json` 加 .gitignore + 建 `app_setting.example.json` 脱敏模板；③ `git filter-repo`/BFG 清历史；④ 账号 ID 同样脱敏。
