## 一、我亲自验证过的事情

### 1. RCE 漏洞 — 确实存在，真的能执行任意代码

**我做了什么**：
- 读了 `strategy_factory/engine.py` 全文（157 行）
- 读了 `api/factory.py` 的 save_physical_strategy 和 test_syntax_secure 端点
- 搜索了整个项目看 `validate_strategy_code` 在哪被调用了
- 搜索了 `app/api/` 和 `app/strategy_factory/` 看有没有调用 ast_sandbox

**发现的**：
- `strategy_factory/engine.py:52`：`spec.loader.exec_module(module)` — 保存策略时，为了提取 docstring，直接加载并执行用户代码
- `strategy_factory/engine.py:112`：`exec(code_content, local_vars)` — 测试策略时，直接 exec 用户代码
- `app/utils/ast_sandbox.py` 确实存在一个沙箱（禁止 os/sys/subprocess/exec/open 等），但它**只在 `app/agents/strategy_coder.py:55-56` 被调用**——这是 LLM 生成代码的路径
- **API 上传路径（`/api/factory/save_physical_strategy` 和 `/api/factory/test_syntax_secure`）完全没有调用这个沙箱**

**结论**：B 报告说的 RCE 漏洞是真的。任何人 POST 到你的 API，可以：
- 写一个包含 `os.system('del /f C:\\*.*')` 的策略文件
- 保存时 extract_docstring 直接执行了
- test_run 时 exec 又执行一次

但目前你的 API 只在本地跑，所以这个风险只在"本地有人能访问你的端口"时才会发生。

### 2. env-keys 返回明文密钥 — 确实返回明文

**我做了什么**：读了 `app/api/system.py:76-96`

**发现的**：L80 和 L85 确实把完整密钥同时放在返回的 JSON 里：
- `keys["tushare_key"] = v`（明文）

### 3. engine.py 成本常量仍然是硬编码 — 确实没迁到 config

**我做了什么**：读了 `engine.py:330-332`、`:655-662`、`:880-887`

**发现的**：
- `TRADE_COST_BUY = 0.125`、`TRADE_COST_SELL = 0.175` — 类内硬编码常量，确实还在
- L24 确实 import 了 `calc_buy_cost, calc_sell_revenue`，但 L657/881 用的是类常量 `self.TRADE_COST_BUY / 100`，不是 execution 的函数
- `config/app_setting.json` 的 `backtest.cost` 段有另一套成本率（万2.5 佣金 + 千0.5 印花），但 engine.py 不读它们

**这不是说 engine.py 没扣成本——确实扣了。** 只是扣成本时用的是自己的常量（0.125%/0.175%），不走 execution.py 的 config 化路径。
