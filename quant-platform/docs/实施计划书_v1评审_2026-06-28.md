## 1.2 P0-1（tp1_profit 单位约定冲突）的深度核实

这是作者对我反馈**最关键的回应**。他说我的原始分析中 path-C（engine.py daily_fallback 的 "永不触发"）不准确，实际雷点反方向。让我独立核实。

### 作者描述的两套约定

| 位置 | 约定 | 代码证据 |
|---|---|---|
| config `risk.take_profit_tiers` / `_build_tp_plan` 输出 | **小数**（0.027=2.7%） | `app_setting.json:26` 值 0.027 ✅ |
| engine.py daily_fallback（override 分支） | **百分比**（`tp_price=entry*(1+tp_pct/100)`） | `engine.py:761` `/100` ✅ |
| engine.py daily_fallback（非 override 分支） | **百分比**（`tp_price=entry*(1+tp_pct/100)`） | `engine.py:931` 同 `/100` ✅ |

### 作者说 daily_fallback 的「真正雷点」是什么？

关键区分：`engine.py:761` 是 `_simulate_trade_v2` 内的代码（override 分支），而 `engine.py:931` 是 `_simulate_trade_daily_fallback` 内的代码。**两个函数都做 `tp_pct / 100`**。

但 `engine.py:842-858` 的非 override 分支走 `settings.staged_take_profit` → 读 `app_setting.json` 的 `risk.take_profit_tiers` → `profit_pct=0.027`（小数）→ 进入 daily_fallback 的 L931 `realized_pnl += tp_pct * actual_sell`。

等等——**L931 不做 `/100`**！让我重新核实。

```python
# engine.py:931 (daily_fallback)
tp_pct = stage.get("profit_pct", 999.0)
realized_pnl += tp_pct * actual_sell   # ← 不做 /100！
```

对比 `engine.py:760-761`（v2 同位置）：
```python
tp_pct = stage.get("profit_pct", 999.0)
tp_price = entry_price * (1 + tp_pct / 100)   # ← 做 /100
```

**所以两个函数的处理不同**：
- v2（L761）：`tp_pct / 100` → 如果 profit_pct=0.027（小数），结果是 +0.027%，一开盘触发 ✅（作者说的小雷）
- daily_fallback（L932）：`tp_pct * actual_sell` **不做任何转换** → 如果 profit_pct=0.027（小数），pct * ratio = 0.027 * 0.3 = 0.0081（即 0.81% pnl），这是错的但不是"一开盘触发"
- daily_fallback（L932）：如果 profit_pct=3.0（百分比），pct * ratio = 3.0 * 0.3 = 0.9（即 90% pnl），严重高估

**作者的"真正雷点"分析**：他说"若 tp_pct=0.027 → 除以 100 = 0.00027 → `entry*(1+0.00027)` = +0.027% 止盈目标，几乎一开盘触发"——这是针对 **override 分支走 v2**（L761 做 /100）的情况。非 override 分支走 daily_fallback（L932 不做 /100），其 pnl 计算是另一个 bug（名义收益问题，已在回测-C2 覆盖）。

**结论**：作者的 P0-1 分析是**对的，且比我原始反馈更精确**。他正确区分了 v2 的 `/100`（消费端按百分比期望）和 daily_fallback 的不做转换（消费端什么都不做），两处消费端的单位处理不同，导致同一个 config 值在不同路径产生不同效果。

### P0-1 修复方案评价

"统一收口"建议——config 与内部传递一律小数——是正确的。但需要同步修改：
1. `api/backtest.py:251` 写入端归一化
2. `engine.py:842-856` 非 override 分支读 config 后的处理
3. `engine.py:931` 的 pnl 计算公式
4. 确认 `_fast_simulate` 的 tp_pct 单位

这些全部标在计划书里，方案完整。
