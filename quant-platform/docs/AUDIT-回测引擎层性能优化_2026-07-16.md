## 逐项验证

### 改动 A — build_context 参数预解包 — **PASS**

- **默认值对齐**(零差异基础):`exit_rules.py:409-428` `precompute_params` 的 18 个字段,与原 `build_context` 的 `params.get(k, default)` **逐字段、逐默认值完全一致**(hard_stop=-0.06 / trail_activate=0.05 / trail_dd=0.02 / time_exit_days=7 / ... priority_mode="trailing_first")。`breakeven_threshold`↔`breakeven_threshold_pct` 的 key 名映射是有意为之,值对齐。
- **时序正确**:`simple_runner.py:57-67` 中 `take_profit_tiers` 补齐(line 65)在 `precompute_params`(line 67)**之前**,`_ctx_params` 拿到的是补齐后的 tiers。
- **向后兼容**:`build_context` 新增 `precomputed=None` 默认参数,未传入时回退到原地 `params.get`(日内路径 421/440 不受影响)。

### 改动 B — 成本配置缓存 — **PASS(范围声明不完整 → WARNING)**

- FastEngine 路径已正确复用:`simple_runner.py:130` `calc_buy_cost(px, sh, cfg=self._cost_cfg)`、`:185` `realized_pnl(..., cfg=self._cost_cfg, ...)`。
- **遗漏(非 bug)**:`simple_runner.py:478` 和 `tdx_runner.py:445` 的日内路径 `calc_buy_cost(px, sh)` 未传 cfg。这两处不在 FastEngine 内,无 `self._cost_cfg` 可用,仍走 `get_cost_cfg()` 每次现取。**正确性无影响**(settings 整场不变,结果一致),但**性能收益未覆盖日内回测**。
- 报告"buy/sell 复用"措辞应限定为 FastEngine 路径。

### 改动 C2 — 消除双重 _is_signal_value — **PASS**

- 日线路径 `sig_by_code` 现只存"确为信号"的日期(`tdx_runner.py:678`),`pending_buys` 构造(`:767`)不再二次判定。
- 逻辑等价:原 `if has_any`(任一日期是信号)≡ 新 `if code_sigs`(code_sigs 非空);`pending_buys` 最终集合一致。
- **下游安全**:grep 确认日线路径 `sig_by_code` 在 `:767` 之后**再无引用**,仅 `pending_buys` 消费。日内路径(242/265/363)是独立变量,未改动。

### 改动 D — low_cache 粒度修正 — **PASS(零差异)+ WARNING(既存 silent failure)**

- **O(N²) 读盘隐患已除**:`low_map_cache` 按 `code_num` 缓存整只 `{date: low}` 映射,每只股票只 `read_parquet` 一次。原 `(dt_str, code_num)` 粒度会导致同一股票每个日期重读整个 parquet。
- **has_ohlc 逐行判断**:`row_has_ohlc` 局部变量,不再让一行脏数据永久污染整只股票。✅
- **⚠️ 既存 silent failure(非本次引入)**:`_get_low_map` 把 parquet date 列 strftime 成 `'YYYY-MM-DD'`(如 `2025-05-01`),但 `dt_str` 来自 TDX worker 是 `'YYYYMMDD'`(如 `20250501`)。`_lm.get(dt_str)` 永远查不到 → low 恒 fallback 到 close。**原代码同样如此**(`pdf[pdf['date']==dt_str]` 格式不匹配 → 空 row → low=close),故**两边行为一致、零差异成立**。但报告"触发时读同一 parquet,low 值一致"措辞过头——实际是两边都取不到 low,parquet fallback 实质失效(既存 bug,非本次引入)。
- **重跑佐证**:dt_str 格式已实测确认——parquet 样例 `['20180418','20180419','20180420']`(YYYYMMDD)。

### 改动 E — 去 list() + import 提顶层 — **PASS**

- `simple_runner.py:142` `for code, p in self.positions.items()`:循环体只改 Position 属性 + append 到独立 `sells` 列表,**不 del/add positions key** → 去 list() 安全。
- `tdx_runner.py:794` `for code in eng.positions`:循环体只写 `snap`,不碰 `eng.positions` → 安全。
- `exit_rules` import 提到模块顶层(`simple_runner.py:14`),`check_stops` 函数体内 import 已删,未使用的 `RuleContext` import 已清理。

### crash 修复(prev_day → td_list[d_idx-1])— **PASS + WARNING(报告已自述)**

- 崩溃消除:日线循环本无 `prev_day` 变量(grep 确认仅日内路径 361/433/583 有),原代码必抛 NameError。改 `td_list[d_idx-1]` 正确。✅
- **正确性隐患(独立遗留问题)**:前一交易日 snap 若无该股(停牌/首次出现)→ `prev_close=None` → 涨停过滤降级。报告第七节已主动声明,改前改后行为一致,不影响零差异。
