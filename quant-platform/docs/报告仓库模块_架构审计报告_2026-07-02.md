## 🔴 CRITICAL — 致命缺陷 (必须立即修复)

### C1. 历史快照侧边栏完全瘫痪

**文件**: [main.js:1070-1073](static/js/main.js#L1070-L1073)

**现状**:
```javascript
function loadReportsPage() { /* stub */ }
function loadReportsList() { /* stub */ }
function downloadModalMD() { /* stub */ }
function downloadViewerMD() { /* stub */ }
```

**影响**: 报告仓库的核心价值是"存档 → 检索 → 调阅"，但目前只有"生成"链路可用。用户生成了报告后，**永远无法再找到它**。侧边栏、分页、搜索全部是空壳。

**严重性**: 这不是 bug，而是**功能缺失**。一个"仓库"不能取东西，等于没有仓库。

**修复方案**:
```javascript
let currentReportPage = 1;
const REPORT_PAGE_SIZE = 15;

async function loadReportsList() {
  const searchInput = document.getElementById('report-search');
  const search = searchInput ? searchInput.value.trim() : '';
  const offset = (currentReportPage - 1) * REPORT_PAGE_SIZE;

  try {
    const r = await fetch(
      `/api/reports/list?limit=${REPORT_PAGE_SIZE}&offset=${offset}&search=${encodeURIComponent(search)}`
    ).then(resp => resp.json());

    if (r.status === 'ok') {
      const listEl = document.getElementById('report-list');
      const { total, data } = r.data;

      listEl.innerHTML = data.map(rep => `
        <div class="strategy-item" onclick="viewReport(${rep.id})" style="cursor:pointer">
          <div style="font-weight:600">${rep.code} ${rep.name || ''}</div>
          <div style="font-size:11px;color:var(--text2)">${rep.created_at || ''}</div>
        </div>
      `).join('');

      const totalPages = Math.max(1, Math.ceil(total / REPORT_PAGE_SIZE));
      document.getElementById('rep-page-info').textContent =
        `${currentReportPage} / ${totalPages}`;
    }
  } catch (e) { console.error('loadReportsList failed:', e); }
}

function loadReportsPage(delta) {
  currentReportPage = Math.max(1, currentReportPage + delta);
  loadReportsList();
}

async function viewReport(id) {
  try {
    const r = await fetch(`/api/reports/content/${id}`).then(resp => resp.json());
    if (r.status === 'ok' && r.data) {
      document.getElementById('report-empty-state').style.display = 'none';
      document.getElementById('report-viewer-container').style.display = 'flex';
      document.getElementById('viewer-report-title').textContent =
        `${r.data.code} ${r.data.name} — AI 深度报告`;
      document.getElementById('viewer-report-content').innerHTML =
        marked.parse(r.data.content || '');
    }
  } catch (e) { console.error('viewReport failed:', e); }
}

function downloadViewerMD() {
  const title = document.getElementById('viewer-report-title')?.textContent || 'report';
  const content = document.getElementById('viewer-report-content')?.innerText || '';
  const blob = new Blob([content], { type: 'text/markdown' });
  const a = document.createElement('a');
  a.href = URL.createObjectURL(blob);
  a.download = title.replace(/\s+/g, '_') + '.md';
  a.click();
}
```

### C2. 报告只能存不能删 — 数据只增不减

**文件**: [agents.py](app/api/agents.py) · [duckdb_manager.py](database/duckdb_manager.py)

**现状**: API 层只有 `save` / `list` / `get_by_id`，**没有 delete 和 update**。DB 层也没有 `delete_ai_report()` 方法。

**影响**:
- 错误生成的垃圾报告无法清理
- 同一股票重复生成 N 份报告，无法去重
- 长期运行后 `ai_reports` 表无限膨胀

**修复方案**:
```python
# duckdb_manager.py 新增
def delete_ai_report(self, report_id: int) -> bool:
    """删除指定报告"""
    try:
        self.conn.execute("DELETE FROM ai_reports WHERE id = ?", [report_id])
        self.conn.commit()
        return True
    except Exception as e:
        log.error(f"Delete AI report {report_id} failed: {e}")
        return False

# agents.py 新增
@router.delete("/api/reports/{report_id}")
def delete_ai_report(report_id: int):
    try:
        ok = db.delete_ai_report(report_id)
        if ok:
            return {"status": "ok"}
        return {"status": "error", "message": "删除失败"}
    except Exception as e:
        return {"status": "error", "message": str(e)}
```

## 🟠 HIGH — 严重缺陷 (应尽快修复)

### H1. 同一股票可无限生成重复报告

**文件**: [duckdb_manager.py:741-767](database/duckdb_manager.py#L741-L767)

**现状**: `save_ai_report()` 每次都 INSERT 新行，不管该股票是否已有报告。

**影响**: 用户对"贵州茅台"点 10 次"生成报告" = 10 份内容雷同的报告，浪费 LLM 调用费用 + 污染仓库。

**修复方案**: 采用 upsert 策略 — 同一代码同一天只保留最新版：
```python
def save_ai_report(self, code: str, name: str, content: str) -> int:
    clean_code = str(code).split('.')[0]
    today = date.today().isoformat()
    # 检查今日是否已有报告
    existing = self.conn.execute(
        "SELECT id FROM ai_reports WHERE code = ? AND CAST(created_at AS DATE) = ?",
        [clean_code, today]
    ).fetchone()
    if existing:
        # 更新已有报告
        self.conn.execute(
            "UPDATE ai_reports SET content = ?, name = ?, created_at = NOW() WHERE id = ?",
            [content, name, existing[0]]
        )
        self.conn.commit()
        return existing[0]
    # 插入新报告
    ...
```

### H2. 两套 AI 生成引擎并存，调用关系混乱

**文件**: [stock_analyst.py](app/agents/stock_analyst.py) vs [committee.py](app/agents/committee.py)

**现状**:
| | stock_analyst.py | committee.py |
|---|---|---|
| 架构 | 单 Agent (DeepSeek) | 多 Agent 红蓝对抗 (LangGraph) |
| 质量 | 低 (单向分析) | 高 (多空博弈 + 仲裁) |
| 实际被调 | ❌ 无人调用 | ✅ `agents.py` 调用 |
| 状态 | 孤儿代码 | 在用 |

**影响**:
- 代码维护者会困惑"到底用哪个"
- `stock_analyst.py` 白白占用代码库空间
- 如果有人误调 `stock_analyst.generate_report()` 会得到低质量报告

**修复方案**: 删除 `stock_analyst.py`，或将它改造为 committee 的 fallback（当 LangGraph 依赖不可用时降级到单 Agent）。

### H3. 报告生成是同步阻塞 — HTTP 可能超时

**文件**: [agents.py:9-33](app/api/agents.py#L9-L33) · [committee.py:155-159](app/agents/committee.py#L155-L159)

**现状**: `generate_ai_report()` 同步调用 LangGraph，内部串行执行 3 次 LLM 调用（bull + bear + manager），加上 Tushare 数据拉取，总耗时可能 30-60 秒。

**影响**:
- FastAPI 默认超时可能触发 504
- 前端长时间无反馈，用户以为卡死
- 并发请求会阻塞工作线程

**修复方案**: 改为异步任务模式：
```python
import asyncio
from concurrent.futures import ThreadPoolExecutor

_report_tasks = {}  # task_id → status/result

@router.post("/api/agents/analyze/{stock_code}")
async def start_analysis(stock_code: str, name: str = ""):
    task_id = f"report_{stock_code}_{int(time.time())}"
    _report_tasks[task_id] = {"status": "running", "progress": 0}
    # 后台线程执行
    loop = asyncio.get_event_loop()
    loop.run_in_executor(
        ThreadPoolExecutor(max_workers=2),
        _do_generate, task_id, stock_code, name
    )
    return {"status": "started", "task_id": task_id}

@router.get("/api/agents/task/{task_id}")
def get_task_status(task_id: str):
    return _report_tasks.get(task_id, {"status": "not_found"})
```

### M3. Tushare 数据获取无校验 — 空 context 直送 LLM

**文件**: [tushare_api.py:71-100](app/data_manager/tushare_api.py#L71-L100)

**现状**: `get_ai_context()` 在 Tushare 未配置时返回 `"Tushare API is not configured."`，这个字符串直接喂给 LLM 生成"分析报告"。

**影响**: 产出的报告完全是垃圾 — AI 对一句错误信息做"深度分析"毫无价值。

**修复方案**:
```python
def get_ai_context(self, code: str) -> str:
    if not self.pro:
        raise ValueError("Tushare API 未配置，无法获取标的数据")
    context = self._build_context(code)
    if len(context) < 100:
        raise ValueError(f"标的 {code} 数据不足，无法生成有效报告")
    return context
```

## 🔵 LOW — 轻微问题 (可选优化)

### L1. `reporter.py` 命名冲突

**文件**: [reporter.py](app/sim_trader/reporter.py)

这个文件是模拟盘的每日/最终报告生成器，与 AI 报告仓库毫无关系。文件名 `reporter.py` 容易让开发者误以为它是报告仓库的一部分。

**建议**: 重命名为 `sim_trader_report.py` 或 `backtest_report.py`。

### L2. ai_reports 表缺少索引

**文件**: [duckdb_manager.py:230-241](database/duckdb_manager.py#L230-L241)

`ai_reports` 表的 `code` 和 `created_at` 字段没有索引，随着报告量增加，搜索和列表查询会变慢。

**建议**:
```sql
CREATE INDEX IF NOT EXISTS idx_ai_reports_code ON ai_reports(code);
CREATE INDEX IF NOT EXISTS idx_ai_reports_created ON ai_reports(created_at);
```

### L3. 报告内容没有摘要字段

列表页只能显示 `code` + `name` + `created_at`，无法预览报告内容或评分。

**建议**: 增加 `summary` 和 `score` 字段，在 AI 生成时自动提取。
