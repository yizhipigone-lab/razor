# 优化思考建议 — 基于 EOD 设计前提的迭代方案

> 撰写：2026-06-28（周日）｜作者：Claude（本会话）
> 前提：已确认两条 EOD 交易设计（`project_eod_trading_design.md`）——①尾盘选股+close 成交是有意设计；②当天卖出资金回笼用于尾盘买入是正确的 A 股 T+0 资金回转。
> 定位：本文不再复述问题清单（见审计报告 + 三方交叉验证），而是给**带优先级、带工程量、带验证口径**的优化路线。

---

## 0. 一句话

EOD 前提澄清后，真正值得投入的优化只剩**三件事**，按收益/风险排序：
**① 让所有路径扣成本（含 AI 寻优）→ ② 修过拟合选优口径 → ③ 统一数据层复权与口径。** 其余都是周边增强。close 成交、资金回笼**不要动**。

---

## 1. 优化的「不要做」清单（EOD 前提下的反向约束）

先明确哪些"看似该优化"的方向其实是错的，避免白费功夫、破坏正确设计：

| 不要做 | 原因 |
|---|---|
| ❌ 把买入价改成次日 open | 违背尾盘交易设计；会让回测偏离真实策略意图 |
| ❌ 给"卖出→买入资金回笼"加买入→卖出方向拦截 | 资金回笼当日可用是正确 A 股行为；T+1 只限制买入→卖出方向，资金回笼不受限。**勿用"T+1"笼统表述，避免与资金回笼混淆** |
| ❌ 把 close 成交标成"未来函数"去修 | 它是简化假设，不是 bug |
| ❌ 为追求"四引擎结果一致"而强行合并引擎 | 引擎定位不同（日线/5m/1m/严格）；目标是**口径可比+各自正确**，不是抹平差异 |

---

## 2. 三件主任务（按优先级）

### 任务一：全路径成本一致化（最高优先，收益最大）

**为什么最优先**：这是唯一能同时修复"回测虚高 + AI 寻优错误前提 + 模拟盘虚高"三处的根因。EOD 前提不影响它——成本与成交价格假设正交。

**精确范围**（基于成本真相矩阵，只补"不扣"的路径）：

| 路径 | 现状 | 改造 |
|---|---|---|
| `BacktestEngine._simulate_trade_daily_fallback` | 零成本 + 名义档位收益 | 接 `execution.calc_buy_cost/calc_sell_revenue`；止盈按 `entry*(1+tp_pct)` 真实价 |
| `simple_runner/_run_intraday_backtest`（5m/1m） | 零成本 | 内联成交改走 execution |
| `tdx_runner/_run_intraday_backtest`（5m/1m） | 零成本 | 同上 |
| `ai_optimizer._fast_simulate`（1m） | **双重 bug**：①零成本 ②名义档位收益 | ①接 execution 扣成本；②修 `ai_optimizer.py:641` `realized += tp_pct * actual`（档位目标%直接当收益）→ 按 `entry*(1+tp_pct/100)` 真实价差算。**否则只扣成本不修名义收益，1m 寻优目标函数仍偏** |
| `sim_trader/SimTraderEngine` | 零成本 | 加可配置成本层（佣金万2.5最低5元/印花千1/过户万0.1/滑点）|

**配套**（否则改了也不生效）：
- 接通 `apply_costs` 下传链：`engine.py:277` 调用 `_simulate_trade_daily_fallback` 时传 `apply_costs`。
- 成本率从 `config/app_setting.json` 读，**禁止硬编码**（遵循 config 唯一真相源）。

**验证口径**：改造前 `git tag v-pre-cost-fix` + 备份 `output/`；改造后跑 `scripts/run_backtest.py` 78 公式全量基线（预计 6+ 小时），新旧对比写 `docs/backtest_baseline_diff_*.md`。预期：所有策略收益、胜率、PF 系统性下降，下降幅度≈交易频率×单边成本。**若某策略下降后转负，说明它本就靠零成本幻觉支撑——这正是要暴露的。**

---

### 任务二：AI 寻优反过拟合（次高优先）

**三处一起改，否则单改无效**：

1. **目标函数口径**（`ai_optimizer.py:844`）：objective 返回 `valid_score` 而非全样本 `score`，让 Optuna 真正在验证集上爬山。
2. **最终选优口径**（`ai_optimizer.py:1132-1138`）：`_sort_key` 改 `(valid_score, wfe)`，与 Top-10 排序一致——消除"防过拟合被自己抵消"。
3. **样本切分**（`ai_optimizer.py:1060-1069`）：按**自然交易日** 70/20/10 切，而非信号序号；test 集严格隔离只做最终展示，绝不参与任何选优。

**叠加任务一后**：TDX 5m 路径的 `ret_pct` 不再是裸 pnl（`ai_optimizer.py:470`），过拟合的"错误前提"根因一并消除。

**结构性建议**（中期）：
- 参数维度 10~12 个 vs trial 62 次，自由度严重不足。**先固定 ratio 类参数只搜 pct**，或把 trial 提到 ≥200。
- LHS 种子参数化 + `np.random.default_rng(seed)` 局部生成器（消除全局 RNG 污染 + 每次探索点相同）。
- 目标函数加回撤惩罚 + 最小交易数门槛（避免选出"8 笔大赚但回撤 40%"的脆弱参数）。

**验证口径**：用同一策略，对比"旧 IS 选优 vs 新 valid 选优"的 **test 集** 表现——若新方案 test 集更稳、IS-test gap 更小，则过拟合确实被抑制。

### 任务三：数据层口径统一（中优先，但影响面最广）

**三件，按危险度**：

1. **min5 列名统一**（数据-C1，无副作用，可立即做）：`engine.py:152` 落盘前把 `date` rename 为 `datetime`；修 `engine.py:147` 的重复键 rename；`load_all_bars` 对 min5 做列名兼容。**否则所有分钟级回测/盘中监控数据读不到。**
2. **日线复权口径统一**（数据-C3，需全库重同步）：全市场同步统一前复权（`pro.daily`+`adj_factor` 自复权，或逐股 `pro_bar(adj='qfq')`），消除除权日跳空污染信号。文件记录复权方式标记。
3. **双时段幂等**（数据-C4）：08:30 盘前只做昨日补齐+股票列表，当日数据同步只放 17:30；`run_daily_pipeline` 加当日幂等键。

## 4. 执行纪律（贯穿所有任务）

1. **每个任务独立分支** + 改前 `git tag` + 备份 `output/`，可一键回退。
2. **任务一、二会改历史结果**——必须基线 diff 归档，不照单全收、不跳过对比。
3. **V1 旧基线保留为可访问归档**：任务一改完后 78 公式历史结果全变，把改前结果存为只读版本（`output/backtest_v1_<tag>/` 独立命名 + 前端可切换查看），便于"改前最优策略 vs 改后对应结果"对比。
4. **改完跑最相近的已有用例**（78 公式批跑 / 单股模拟盘），确认 0 报错 0 崩溃再合并。
5. **成本率、滑点、惩罚系数等全部进 config**，禁止散落硬编码。
6. EOD 设计假设在回测结果页**显式标注**，防止后人再把 close 成交误判为 bug。
