## 二、根因：两个被高频调用的 O(n) 函数

### 元凶 ①：`FastEngine._td` 线性扫描持仓天数

**位置**：[simple_runner.py:73-74](../app/backtest/simple_runner.py#L73-L74)

```python
def _td(self, d1, d2):
    return sum(1 for t in self.td_list if d1 <= t <= d2)
```

每次调用都把整个 `td_list`（2383 天）从头扫到尾。

**调用点**：[simple_runner.py:117](../app/backtest/simple_runner.py#L117)（`check_stops` 每持仓每天）、[simple_runner.py:172](../app/backtest/simple_runner.py#L172)（`sell_phase` 卖出时）。

**复杂度**：2383 天 × 平均 16 只持仓 × 约 2 次/天 ≈ **7.6 万次调用 × 每次 O(2383) ≈ 1.8 亿次比较**。

> 同仓库 [TradingCalendar.trading_days_between](../app/backtest/tdx_runner.py#L471) 已是 O(1)，日内分支用了，日线分支漏了。

### 元凶 ②：`_run_daily_backtest` 每天全量扫描信号股

**位置**：[tdx_runner.py:798-801](../app/backtest/tdx_runner.py#L798-L801)

```python
signals_today = sorted(
    code for code, sigs in sig_by_code.items()        # 每天遍历全部信号股
    if _is_signal_value(sigs.get(d_str))
)
```

**实测数据**（缓存 parquet 统计）：

| 项目 | 数值 |
|---|---|
| `sig_by_code` 规模（曾出现信号的股票） | **5421 只** |
| 整个区间真实信号条数 | 仅 **24980 条** |
| 引擎主循环扫描次数（2383 天 × 5421 只） | **≈ 1290 万次** |
| 平均每天真实信号数 | ≈ 10 条 |

主循环内为了找 24980 条真信号扫了 1290 万次。仓库已有正确写法（[simple_runner.py:694-696](../app/backtest/simple_runner.py#L694-L696) `sbd`、[tdx_runner.py:355-363](../app/backtest/tdx_runner.py#L355-L363) `pending_buys`），日线分支漏抄。

## 三、改动详情

### 改动 1：`_td` 查表化（O(n) → O(1)）

**文件**：`app/backtest/simple_runner.py`

**改 `FastEngine.__init__`**（[第 53-54 行](../app/backtest/simple_runner.py#L53-L54)），`self.td_list = td_list` 之后新增：

```python
self.td_list = td_list
self._td_index = {d: i for i, d in enumerate(td_list)}   # 新增：日期 → 序号
```

**改 `_td` 方法**（[第 73-74 行](../app/backtest/simple_runner.py#L73-L74)）：

```python
def _td(self, d1, d2):
    # 持仓天数 = 交易日序号之差 + 1（含买入日与当天，与原 sum(<=) 语义一致）
    # v2 防御：用 getattr 兼容"重写 __init__ 不调 super 的子类"（若属性缺失则走线性扫描兜底）
    idx = getattr(self, '_td_index', None)
    if idx is None:
        return sum(1 for t in self.td_list if d1 <= t <= d2)
    i1 = idx.get(d1)
    i2 = idx.get(d2)
    if i1 is None or i2 is None:
        return sum(1 for t in self.td_list if d1 <= t <= d2)
    return max(0, i2 - i1 + 1)   # v2: max(0,...) 防御 d1>d2 返回负数
```

**语义等价性证明**（d1≤d2 且都在 td_list 时）：`i2-i1+1` ≡ `sum(1 for t in td_list if d1<=t<=d2)`。

**v2 加固的三条边界**：
1. `getattr` → 子类若重写 `__init__` 不调 super（缺 `_td_index`），退回线性扫描，不崩。
2. `i1/i2 is None` → d1 或 d2 不在 td_list（如非交易日/超界），退回线性扫描。
3. `max(0, ...)` → 防御 d1>d2（当前业务恒不成立，但防脏数据引发 hold_days 负数连锁）。

### 改动 2：信号反向索引（主循环 O(天×股) → O(天)）

**文件**：`app/backtest/tdx_runner.py`，函数 `_run_daily_backtest`

**Step A** —— 主循环前预建反向索引（插在 [第 769 行 `td_list = sorted(...)`](../app/backtest/tdx_runner.py#L769) 之后）：

```python
td_list = sorted(date.fromisoformat(d) for d in prices_by_date.keys())

# 新增：预建 {日期: [当天有信号的 code 列表]}
pending_buys = defaultdict(list)
for code, sigs in sig_by_code.items():
    for dt_str, zp in sigs.items():
        if _is_signal_value(zp):
            pending_buys[dt_str].append(code)
```

**Step B** —— 主循环内替换查找（[第 798-801 行](../app/backtest/tdx_runner.py#L798-L801)）：

```python
signals_today = sorted(pending_buys.get(d_str, []))
```

**结果一致性证明**：`sig_by_code` 是 dict（code 唯一），`pending_buys` 构建无重复；`sorted(pending_buys[d_str])` 与原 `sorted(code for code, sigs in ... if ...)` 产出同集合、同排序键 → `signals_today` 完全一致 → 买入顺序/资金分配/成交结果不变。

**v2 成本修正**：预建遍历 `sig_by_code` 全部条目，因每只股票存了区间内**所有日期**（不只信号日，见 [tdx_runner.py:697-698](../app/backtest/tdx_runner.py#L697-L698)），总条目 ≈ 5421 × 1390 ≈ **753 万**（不是 v1 误写的 24980）。这是一次性成本，相比原"主循环每天重复扫 5421 只"仍大省——主循环内彻底消除了 1290 万次全量扫描。

## 四、预期收益

### 单次回测

| 阶段 | 现状 | 改后 |

| 数据获取（subprocess+缓存） | ~19 分钟 | 命中缓存 ~10 秒 |

### 局部加速倍数 vs 端到端（v2 澄清）

| 优化点 | 局部加速 | 说明 |
|---|---|---|
| `_td` 查表 | 这部分约 **100×+** | 1.8 亿次比较 → 7.6 万次查表 |

> v1 措辞易让人误以为"整体快 500 倍"。实际整体快 6~10 倍，已是巨大改善。

AI 优化器 TDX 模式每个 trial 都调一次 `run_tdx_backtest`（[ai_optimizer.py:457-468](../app/backtest/ai_optimizer.py#L457-L468)），默认 62 个 trial：

| 场景 | 现状（估算） | 改后（估算） |

| 单次 trial 回测（缓存命中） | 1.5~2.5 小时 | 10~20 分钟 |
| AI 优化 62 trial 串行 | **约 4~6 天** | **约 10~20 小时** |

改动 1+2 让 AI 优化器从"基本跑不完"变成"一夜能跑完"。**这份优化的真实价值主要在这里**，不只是单次回测提速。

## 五、验证方法（v2 强化）

### 前置条件（必须冻结，否则对比无意义）

1. **同一个 tdx_cache 文件**：基线跑与验证跑必须命中同一个缓存 parquet（`output/tdx_cache/746ce9888f972f02.parquet`）。验证期间**不要清缓存**。
2. **冻结通达信公式文件**：`PriCS.dat / PriGS.dat / PriLoc.dat` 的 mtime 变化会让公式指纹变 → 缓存 key 变 → 数据重算且可能微变。验证期间不要在通达信里改任何公式。
3. **同一份 `backtest_config.json`**：风控参数、区间、公式名完全一致。验证期间不要动系统设置页。
4. **同 Python 环境 / 同依赖版本**。

### 验证流程

**Step 1：基线**。等当前在跑的回测（老代码）出结果，存 `bt_baseline_2020_2026.json`。

**Step 2：先小区间验逻辑**（v2 新增，省试错成本）。改完代码后，先用**小区间**（如 2025-01-01 ~ 2026-07-11，约 360 交易日）跑一次老代码基线 + 一次新代码，diff。小区间跑完约 1-2 分钟，快速确认逻辑等价。

**Step 3：全量验数值**。小区间全绿后，再用 2020-2026 全量跑新代码，和 Step 1 基线 diff。

**Step 4：双引擎交叉**。同时跑一个 Python 策略日线（如 `ma5_angle`），确认 `FastEngine` 改动两条路径都不变。

**Step 5：AI 优化器抽样**（v2 新增）。跑一次 AI 优化器 TDX 模式，2-3 个 trial，确认 trial 的 pnl 与改动前一致（这是 v1 完全漏掉的验证路径）。

### 量化容差判据（v2 新增）

| 字段 | 判据 |
|---|---|
| `summary.trades`（交易笔数） | **必须完全相等** |
| `summary.signals` / `buy_signals` | **必须完全相等** |
| `summary.exit_reasons`（各退出原因计数） | **必须完全相等** |
| `summary.win_rate`（0.1% 精度） | **必须完全相等** |
| `summary.total_return` / `final_equity` | `|diff| < 1e-6` 算通过 |
| `summary.sharpe` / `sortino` / `calmar` | `|diff| < 0.01` 算通过 |
| `equity` 曲线逐点 | 完全相同（改动不改计算路径，理论上零差异） |

> 任何"必须完全相等"项不一致 → 立即回滚排查。理论改动 1+2 不改变任何浮点计算路径，整数位差异即说明引入了 bug。

### AI 优化器（v1 误写"不影响"，v2 修正）

AI 优化器有**两条路径**：

| AI 优化器模式 | 回测引擎 | 是否受改动影响 |
|---|---|---|
| **TDX 模式**（[ai_optimizer.py:457](../app/backtest/ai_optimizer.py#L457)） | `run_tdx_backtest` → `FastEngine` | ✅ **受改动 1+2 影响**（更快、需验证） |
| **Python 模式**（[ai_optimizer.py:29](../app/backtest/ai_optimizer.py#L29)） | `BacktestEngine`（engine.py，独立一套） | ❌ 不受影响 |

→ **AI 优化器 TDX 模式必须纳入验证（第五节 Step 5）**。

### BacktestEngine vs FastEngine（v2 区分澄清）

| 引擎 | 文件 | 被谁用 |
|---|---|---|
| `BacktestEngine` | `app/backtest/engine.py` | `/api/backtest`（老接口）、AI 优化器 Python 模式 |
| `FastEngine` | `app/backtest/simple_runner.py` | `/api/backtest/run-simple`（前端 simple_bt）、`tdx_runner`、各 scripts |

改动 1+2 只动 `FastEngine`，不碰 `BacktestEngine`。

### 不受影响

日内回测（5m/1m）用 `_run_intraday_backtest` 独立循环 + `TradingCalendar`，不实例化 `FastEngine`、不用 `_td`，不受改动 1 影响；其信号查找已是 `pending_buys` 模式，不受改动 2 影响。
