```python

    """动态更新扫描间隔（同时持久化到 app_setting.json）"""
    self._exit_scan_interval = max(1.0, min(300.0, seconds))
    from core.settings import settings
    settings.set("live_trader", "exit_scan_interval_sec", self._exit_scan_interval, save=True)
```

#### 2.3 新增 API 端点

```python
# 文件: app/live_trader/main.py

@app.get("/live/config/scan-interval")
async def get_scan_interval():
    """查询离场扫描间隔（从 scheduler 运行时值读取，不读 frozen config）"""
    scheduler = _state.get("scheduler")
    config = _state.get("config")
    if scheduler:
        return {"interval_sec": scheduler._exit_scan_interval}
    if config:
        return {"interval_sec": config.exit_scan_interval_sec}
    raise HTTPException(503, "未初始化")

@app.put("/live/config/scan-interval")
async def set_scan_interval(body: dict):
    scheduler = _state.get("scheduler")
    if not scheduler:
        raise HTTPException(503, "调度器未初始化")
    val = float(body.get("interval_sec", 10))
    if val < 1 or val > 300:
        raise HTTPException(400, "扫描间隔须在 1-300 秒之间")
    scheduler.set_scan_interval(val)
    return {"interval_sec": val, "status": "ok"}
```

#### 3.3 🔴 host.docker.internal 默认值修复（4 处功能缺陷）

**这是真实 BUG**: 在非 Docker 的 Windows 环境下，`host.docker.internal` 无法解析，导致连接失败。

| # | 文件 | 行号 | 改为 |
|---|------|------|------|
| F1 | `cron_jobs.py` | 544 | `http://host.docker.internal:8001` → `http://127.0.0.1:8001` |
| F2 | `qmt.py` | 23 | `host.docker.internal` → `127.0.0.1` |
| F3 | `data_sync.py` | 164 | `host.docker.internal` → `127.0.0.1` |
| F4 | `qmt_index_sync.py` | 95 | `host.docker.internal` → `127.0.0.1` |

修改方式: 将默认值从 `host.docker.internal` 改为 `127.0.0.1`。环境变量 `LIVE_TRADER_HOST` / `QMT_PROXY_HOST` 仍可覆盖（Docker 环境下设为 `host.docker.internal` 即可）。

`.env` 中已有 `QMT_PROXY_HOST=127.0.0.1`，所以当前 F2/F3/F4 实际不会触发。但 F1（`LIVE_TRADER_URL`）未在 `.env` 中设置，**确实会用到错误默认值**。

A股量化交易平台，支持 TDX 公式选股、模拟盘/实盘自动交易、回测分析。

## 快速启动
- 环境要求（Python 3.13、QMT 迷你版、通达信客户端、TDX 公式选股依赖）
- 环境变量（QMT_ACCOUNT_ID 必须设置、QMT_PATH 指向 QMT 安装目录）
- start.bat / stop.bat
- 端口说明（8888 API 服务 / 8001 实盘服务）

## 架构概览
- 双进程架构图（8888 + 8001）
- 数据流：TDX 选股 → 模拟盘/实盘 → QMT 下单
- 关键配置文件

## 功能清单
### ✅ 模拟盘交易
- TDX 公式选股（策略名可配置）
- 自动买卖、止盈止损（8 条退出规则）
- 盘中监控（tick 驱动，默认只告警）
- 连败保护（减半/暂停）

### ✅ 实盘交易
- 信号桥接（API 服务 → 实盘服务推送）
- 9 道风控闸门
- Kill Switch 紧急刹车
- 手动对账（三方比对）
- 审计回放
- 持仓同步（QMT ↔ 本地）
- dry-run / live 模式切换

### ✅ 选股系统
- TDX 通达信公式选股桥接
- Python 策略选股
- 策略工厂（AI 辅助翻译通达信公式）

### ✅ 回测系统
- TDX 回测 / 简单回测 / 严格回测
- AI 参数优化

### ✅ 热点板块
- 概念热度 / 行业资金流

### ✅ 行情数据
- QMT 实时行情（首选）
- 腾讯 HTTP（回退）
- Parquet 历史数据（兜底）

## 六、不做什么（YAGNI 清单）

| 不做 | 原因 |
|------|------|
| 策略版本管理 | 用户只换名字 |
| 策略参数录入 | 用户明确说不需要 |
| Tick 驱动硬止损 | 中期优化，本次不做 |
| 除权跳空保护移植到实盘 | 本次未涉及 |
| frozen dataclass 重构 | 改动太大，用 scheduler 独立属性绕过 |
| 前端 JS/HTML 中的 QUANTQQ 硬编码 | 本次不改（A9-A14，约 8 处），独立排期。理由：前端改造范围大，需设计策略名动态渲染机制，与后端配置改动解耦 |
| C 类 Fallback 默认值里的 "QUANTQQ" | 兜底逻辑正确，不需要改 |
| D 类 scripts/ 和 tests/ 里的 "QUANTQQ" | 独立工具和测试数据 |
| qmt_proxy_server.py 废弃文件 | 已废弃，改了也没人看 |

## 七、回滚预案

- 每个任务独立 commit，出问题 `git revert` 单个 commit
- 任务 2 新增 config 字段，旧配置文件缺字段时 fallback 到 60.0（与原行为一致，零破坏）
- 任务 3.3 改默认值后，Docker 环境需设 `LIVE_TRADER_URL=http://host.docker.internal:8001`
- 任务 3 注释改动零风险 revert
