# 项目基本要求与开发规则

## 1. 核心原则
*   **严禁使用易封锁或抓包接口**：出于稳定性考虑，本项目所有数据抓取、实时行情、指数拉取等功能**严禁使用**东方财富 (EastMoney)、新浪 (Sina)、腾讯 (Tencent) 的非官方抓包 API 和 AKShare 库。
*   **优先数据源**：
    *   **实时行情与交易主链路**：**全盘使用 QMT**（通过 HTTP 代理模式）。
    *   **历史数据备份与收割**：**使用 Tushare** 作为离线数据池的补充来源。

## 2. 交易网关与环境依赖
*   **废弃 Windows 绑定依赖**：为确保系统能在 Headless 的 Linux Docker 容器中长期运行，系统**已全面剔除** `easytrader`、`pywinauto`、`PySide6`、`vnpy` 等只跑在 Windows 下的包。
*   **实盘代理模式**：系统内的 `QMTGateway` 运行在隔离沙盒内，通过向宿主机的 `http://host.docker.internal:8081/api` 发送 HTTP 指令完成下单，不在容器内生硬绑定 QMT 客户端。

## 3. 分布式架构与 Docker 部署
*   **三服务职能分离**：
    *   `api-server`: 专职对外提供 FastAPI Web 服务，不允许在主循环中运行阻塞任务。
    *   `task-worker`: 通过 `cron_jobs.py` 独立起盘，专职在后台收割 Tushare 数据和跑 VectorBT 回测，崩溃不影响前端。
    *   `redis`: 作为进程间高速消息总线与临时状态缓存。
*   **DuckDB 读写自律**：盘中高频时段，API Server 应尽量对 DuckDB 保持只读模式（`read_only=True`）规避写锁；重度数据灌入（盘后收割）全权交由 Task Worker 独占写锁完成。

## 4. 预览与测试原则 (全局控制)
*   **自检服务状态**：以后每次邀请用户去前端体验或预览时，必须**自行在后台启动对应服务 (如 FastAPI)**，并利用诸如 `curl` 或 `browser_subagent` 工具自行确认后端是否启动成功、前端页面是否能正常加载。
*   **拒绝白内障式交接**：坚决避免让用户跑到前端去体验后，发现服务根本没起或者页面报错，再跑回这里反馈。把“自测跑通再交付验收”作为此项目全过程的必须实施原则。

## 5. 股票代码规范
*   **后缀强制性**：所有传递给交易网关的股票代码**必须强制携带后缀**。
    *   **6开头**股票/ETF -> `.SH` (如 `600519.SH`)
    *   **0或3开头**股票 -> `.SZ` (如 `000001.SZ`, `300120.SZ`)
    *   **指数处理**：上证指数强制为 `000001.SH`，深证成指为 `399001.SZ`。
    *   **5开头**基金/ETF -> `.SH`。
